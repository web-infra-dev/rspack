# HotModuleReplacementPlugin

此插件用于实现 HMR（hot module replacement）。

## 示例

启用 HMR 非常简单，在大多数场景下无需额外配置。

注意 HMR 不能被用于生产构建，因此你需要通过 `process.env.NODE_ENV` 来判断当前是否是开发环境。

```js title="rspack.config.mjs"
import { rspack } from '@rspack/core';
const isDev = process.env.NODE_ENV === 'development';

export default {
  plugins: [isDev && new rspack.HotModuleReplacementPlugin()],
};
```

## 运行时 API

当你注册 `HotModuleReplacementPlugin` 插件后，Rspack 会注入 HMR 相关的运行时 API，例如 `module.hot` 和 `import.meta.webpackHot`。

详见 [模块热替换 API](/api/runtime-api/hmr)。

## 热更新清单 \{#hot-update-manifest}

HMR 期间，运行时会读取 `hot-update.json` 清单，了解哪些 chunk 需要更新，哪些 chunk 或模块需要移除。清单中记录的是 ID，更新后的 JavaScript 代码位于单独的 `hot-update.js` 文件中。

例如，下面的清单表示更新 `main` chunk 的 JavaScript 和内置 CSS，没有需要移除的 chunk 或模块：

```json
{
  "c": ["main"],
  "r": [],
  "m": [],
  "css": { "c": ["main"] }
}
```

| 字段        | 含义和作用                                                                                        |
| ----------- | ------------------------------------------------------------------------------------------------- |
| `c`         | 有 JavaScript 更新的 chunk ID 列表，运行时据此加载所需的更新文件。                                |
| `r`         | 需要从当前运行时移除的 chunk ID 列表。                                                            |
| `m`         | 需要从当前运行时移除的模块 ID 列表。                                                              |
| `css.c`     | 内置 CSS 需要更新的 chunk ID 列表，运行时会重新加载对应的样式表。                                 |
| `css.r`     | 内置 CSS 已被移除的 chunk ID 列表，运行时会移除对应的旧样式表。                                   |
| `miniCss.c` | 与 `css.c` 类似，但用于 [CssExtractRspackPlugin](/plugins/css-extract-rspack-plugin) 提取的 CSS。 |
| `miniCss.r` | 与 `css.r` 类似，但用于 `CssExtractRspackPlugin` 提取的 CSS。                                     |

`css` 和 `miniCss` 是可选对象，其中的 `c`、`r` 字段为空时会省略。CSS 更新与 JavaScript 更新分开记录，以避免重新加载未变化的样式表。移除 chunk 的 CSS 也不一定会移除 chunk 本身。

清单文件名由 [output.hotUpdateMainFilename](/config/output#outputhotupdatemainfilename) 控制。启用 `output.module: true` 时，清单会以 ES 模块导出，而非纯 JSON。
