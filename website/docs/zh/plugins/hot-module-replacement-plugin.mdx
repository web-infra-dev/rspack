# HotModuleReplacementPlugin

此插件用于实现 HMR（hot module replacement）。

## 示例

启用 HMR 非常简单，在大多数场景下无需额外配置。

注意 HMR 不能被用于生产构建，因此你需要通过 `process.env.NODE_ENV` 来判断当前是否是开发环境。

```js title="rspack.config.mjs"
import { rspack } from '@rspack/core';
const isDev = process.env.NODE_ENV === 'development';

export default {
  plugins: [isDev && new rspack.HotModuleReplacementPlugin()],
};
```

## 运行时 API

当你注册 `HotModuleReplacementPlugin` 插件后，Rspack 会注入 HMR 相关的运行时 API，例如 `module.hot` 和 `import.meta.webpackHot`。

详见 [模块热替换 API](/api/runtime-api/hmr)。

启用 HMR 后，普通 JavaScript chunk 会携带 compilation hash。安装前，Rspack 会将它与当前 runtime hash 比较；不匹配的响应不会注册 module factory，也不会执行 chunk runtime。import 会等待当前更新完成，必要时依次应用后续更新，再重新请求 chunk。如果更新失败，或没有可用的更新能使版本匹配，import 的 Promise 会被拒绝。这一机制不要求 chunk 文件名包含版本信息。

普通 chunk 和 hot update 可以并行下载。较晚返回的旧版本响应会在安装前被拒绝，避免覆盖更新后的 factory。每次加载尝试都会先结束，再等待更新并重试，因此不会阻塞它所等待的 HMR。手动调用 `check(false)` 仍然只准备更新，由调用方决定何时调用 `apply()`。

compilation hash 在读取 chunk 渲染缓存后填入，不改变 chunk hash，也不会关闭增量 chunk hashing。不过，即使模块未变，版本标记仍会改变最终文件内容，因此这些产物仍需重新处理和输出。

自动更新期间仍在加载的 import 也会等待这次更新完成。准备阶段会等待异步 status handler 和所有 hot-update 文件完成。如果准备或应用更新失败，等待这次更新的 import 会被拒绝，不会一直挂起。

## 热更新清单 \{#hot-update-manifest}

热更新时，运行时会读取 `hot-update.json`，确定需要更新的 chunk，以及需要移除的 chunk 或模块。清单中记录了它们的 ID，JavaScript 更新代码则存放在单独的 `*.hot-update.(js|mjs)` 文件中。

下面的示例表示更新 `main` chunk 的 JavaScript 和内置 CSS，无需移除任何 chunk 或模块：

```json
{
  "c": ["main"],
  "r": [],
  "m": [],
  "css": { "c": ["main"] }
}
```

下表中的字段均为 ID 数组：

| 字段        | 含义和作用                                                                                     |
| ----------- | ---------------------------------------------------------------------------------------------- |
| `c`         | 需要更新 JavaScript 的 chunk，运行时会按需加载对应的更新文件。                                 |
| `r`         | 需要从当前运行时移除的 chunk。                                                                 |
| `m`         | 需要从当前运行时移除的模块。                                                                   |
| `css.c`     | 内置 CSS 发生变化的 chunk，运行时会重新加载对应的样式表。                                      |
| `css.r`     | 内置 CSS 已被移除的 chunk，运行时会移除对应的旧样式表。                                        |
| `miniCss.c` | 含义同 `css.c`，用于 [CssExtractRspackPlugin](/plugins/css-extract-rspack-plugin) 提取的 CSS。 |
| `miniCss.r` | 含义同 `css.r`，用于 `CssExtractRspackPlugin` 提取的 CSS。                                     |

`css` 和 `miniCss` 是可选对象，其中的 `c`、`r` 字段为空时会省略。

当 entry 新增 chunk 依赖时，manifest 还可以包含 `load.entries`，将 entry chunk ID 映射到新增的依赖 chunk ID。只有当前 runtime 已加载的 entry 才会触发补载。

补载的 JavaScript 文件在 hot-update 文件名后追加 `.full.js`（`.mjs` 文件则追加 `.full.mjs`），包含该 chunk 的完整 factory。文件在 `check` 阶段下载，在 `apply` 阶段、accept 回调执行前安装。未变化的 factory 会保留已有的模块实例。安装完成后，该 chunk 会参与后续的普通增量更新，即使原来的 importer 已经不再引用它。

你可以通过 [output.hotUpdateMainFilename](/config/output#outputhotupdatemainfilename) 自定义清单文件的名称。如果将 `output.module` 设为 `true`，Rspack 会将清单生成为 ES 模块，并通过默认导出提供清单内容。
