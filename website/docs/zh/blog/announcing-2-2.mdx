### Rsbuild \{#rsbuild}

Rsbuild 2.2 已经与 Rspack 2.2 同步发布。

#### 导入源文本 \{#import-text}

Rsbuild 现在支持使用 import attributes 语法 [`with { type: 'text' }`](https://rsbuild.rs/guide/basic/static-assets#with-import-attributes) 将文件原始内容作为字符串导入：

```ts
import rawCSS from './example.css' with { type: 'text' };
```

> 这与 TC39 的 [Import Text 提案](https://github.com/tc39/proposal-import-text) 保持一致。

#### Node.js 拆包优化 \{#node-split-chunks}

在 Rsbuild 2.2 中，Node.js 构建会默认启用 [chunk 拆分](https://rsbuild.rs/zh/config/split-chunks)，将共享模块提取为独立的 chunk，从而减少重复代码并降低 SSR 应用的内存占用。

下面是 TanStack Start 用户提供的 [实测数据](https://github.com/TanStack/router/issues/8113#issuecomment-5366808113)，测试应用包含 300 个路由和 400 个共享组件：

| 指标                     | Rsbuild 2.1 | Rsbuild 2.2 | 变化         |
| ------------------------ | ----------- | ----------- | ------------ |
| 服务端产物体积           | 298 MB      | 4.1 MB      | **减少 98%** |
| 访问所有路由后的内存占用 | 486 MB      | 129 MB      | **减少 73%** |
| 路由平均访问耗时         | 7.2 ms      | 1.6 ms      | **减少 78%** |
| 共享组件的 HMR 耗时      | 7.1 s       | 0.98 s      | **减少 86%** |

:::tip

- 实际收益取决于项目规模和模块结构。
- 升级后，Node.js 构建可能会生成额外的共享 chunk 文件；如需保留原有行为，可设置 `splitChunks: false`。

:::

#### 支持 Solid v2 RC \{#solid-v2}

Rsbuild 现在支持 [Solid v2 RC](https://www.solidjs.com/blog/solid-2-0-rc-the-big-reveal)。

[`@rsbuild/plugin-solid`](https://rsbuild.rs/zh/plugins/list/plugin-solid) 现在默认使用 Solid 全新的 Rust 编译器。在 Solid 官方的基准测试中，新编译器的编译速度相比此前的 Babel 实现提升 **20 倍以上**。

安装 Beta 版本来体验：

<PackageManagerTabs command="add @rsbuild/plugin-solid@beta -D" />

#### 创建 Octane 项目 \{#octane-template}

`create-rsbuild` 现在支持创建 Octane 项目。[Octane](https://octanejs.dev/) 是一个高性能 JavaScript UI 框架，允许你通过 React API 编写组件，并将其编译为直接的 DOM 代码。

运行以下命令即可创建一个 Octane 项目：

```bash
npx -y create-rsbuild@latest my-app -t octane-ts
```

#### 动态端口 \{#dynamic-port}

Rsbuild 现在支持将 [`server.port`](https://rsbuild.rs/zh/config/server/port#动态端口) 设置为 `0`，由操作系统自动分配一个可用端口：

```ts title="rsbuild.config.ts"
export default {
  server: {
    port: 0,
  },
};
```

这在测试场景中尤其有用，可以避免多个测试同时启动 Rsbuild server 时发生端口冲突。

#### 定制压缩配置 \{#custom-minimizer-configs}

Rsbuild 现在支持同时配置多种压缩选项。

通过为 [`minify.jsOptions`](https://rsbuild.rs/config/output/minify#minifyjsoptions) 传入数组，可以针对不同产物设置不同的压缩策略。例如，仅移除主 bundle 中的 `console` 调用，同时保留其他 bundle 中的调用：

```ts title="rsbuild.config.ts"
export default {
  output: {
    minify: {
      jsOptions: [
        {
          include: /main\./,
          minimizerOptions: {
            compress: { drop_console: true },
          },
        },
        {
          exclude: /main\./,
          minimizerOptions: {
            compress: { drop_console: false },
          },
        },
      ],
    },
  },
};
```

#### 自定义重启流程 \{#restart-api}

基于 Rsbuild 的框架和工具现在可以自行控制重启流程。

Rsbuild 的 JavaScript API 现已支持 [`restart`](https://rsbuild.rs/zh/api/javascript-api/core#restart-handling) 选项，用于处理开发服务器（`rsbuild dev`）或监听构建（`rsbuild build --watch`）的重启请求：

```ts
import { createRsbuild } from '@rsbuild/core';

await createRsbuild({
  restart: (restart) => {
    // 自定义重启逻辑
  },
});
```

Rsbuild 插件也可以通过监听 [`onRestart`](https://rsbuild.rs/zh/plugins/dev/hooks#onrestart) hook 来执行自定义逻辑，例如：

```ts
const myPlugin = () => ({
  setup(api) {
    api.onRestart((context) => {
      console.log('restart!', context);
    });
  },
});
```

#### RSC 插件：Client Component CSS 使用 preinit 加载

Rspack RSC 插件现在对 Client Component CSS 使用 React 的 preinit 方法加载。这样可以保持客户端引用的标识一致性，包括默认导出、具名导出、CommonJS 导出以及非组件导出，均转换为客户端引用（client reference）。

对于 RSC 框架集成而言，这是一项破坏性变更。请将 `react-server-dom-rspack` 升级至 0.1.0。

### Rslib \{#rslib}

#### 支持 TypeScript 7 \{#typescript-7}

Rslib 现已支持使用 [TypeScript 7](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/) 生成类型声明文件。安装 TypeScript 7 后，Rslib 会自动启用原生 TypeScript，显著提升声明文件的生成速度。

#### Rslib 1.0 即将发布 \{#rslib-v1}

[Rslib 1.0 RC](https://github.com/web-infra-dev/rslib/releases/tag/v1.0.0-rc.0) 版本现已发布，正式版也即将到来。如果你正在使用 Rslib 0.x，可以参考 [从 0.x 升级到 v1](https://v1.rslib.rs/zh/guide/upgrade/v0-to-v1) 指南，了解相关不兼容更新。
