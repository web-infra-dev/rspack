# Rspack 2.3 beta 发布公告

_2026 年 10 月 21 日_

<BlogAuthors />

Rspack 2.3 Beta 现已推出！本次更新将 JavaScript 解析器迁移至 SWC Next，新增按代码内容过滤 loader 的能力，并改进了 chunk 拆分、文件监听和内存管理。

本文汇总了 **Rspack 2.2.0 发布后至 2.3.0-beta.0** 的重要变化，不包含 2.2.0 本身的更新。其中部分改进已随 2.2.x 补丁版本发布，升级过这些版本的项目可能已经受益。

欢迎在项目中试用 `2.3.0-beta.0`，帮助我们在正式版发布前验证兼容性。

## 性能 \{#performance}

### JavaScript 解析器迁移 \{#swc-next}

Rspack 2.3 使用 SWC Next 解析 JavaScript，提升大型项目的构建效率，无需调整配置。

> 性能数据待补充：JavaScript 解析耗时、完整构建耗时和内存占用对比。

### 构建流程优化 \{#build-performance}

本轮更新优化了模块分析、CSS 处理、资源输出和构建信息查询，覆盖开发冷启动、生产构建和重建等场景。

> 性能数据待补充：开发冷构建、生产构建和重建耗时对比。

### 实验性缓存改进 \{#cache-improvements}

#### 复用更多构建结果 \{#module-cache}

实验性的 `experiments.newCache` 扩大了缓存覆盖范围，改善重启构建和 HMR 后的缓存复用，适合频繁修改代码或反复启动构建的项目。可以配合[持久化缓存](https://rspack.rs/zh/config/cache)试用：

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
  },
  experiments: {
    newCache: true,
  },
};
```

模块与 loader 的解析缓存可通过 `experiments.newCache.resolver` 单独开启，当前默认关闭。

#### 缓存单个 loader 的结果 \{#loader-cache}

启用 `experiments.newCache` 后，可为 loader 设置 `cache: true`，复用未发生变化的转换结果。缓存已支持 `builtin:swc-loader`，并会在相关依赖变化时失效。

此外，[`cache.maxMemoryGenerations`](https://rspack.rs/zh/config/cache#maxmemorygenerations) 可以控制缓存条目在内存中的保留周期，在内存占用与磁盘读取之间做取舍。

> 性能数据待补充：缓存命中率，以及重启构建和修改依赖后的耗时对比。

### SplitChunks 优化 \{#split-chunks}

#### 发现更多共享模块组合 \{#dedup-depth}

新增的 [`splitChunks.dedupDepth`](https://rspack.rs/zh/plugins/split-chunks-plugin#splitchunksdedupdepth) 可以发现更多可提取的共享模块，减少多页面项目中的重复代码。

生产模式下默认为 `1`，开发模式和 `none` 模式下默认为 `0`。可以根据产物体积与构建耗时调整搜索深度。

#### 减少重复模块 \{#deduplicate-modules}

改进了具名共享 chunk 和嵌套异步 chunk 的去重，减少同一模块在多个产物中重复出现。这些优化自动生效，无需更改配置。

#### 避免拆分后留下过小的 chunk \{#min-remaining-size}

支持了 [`splitChunks.minRemainingSize`](https://rspack.rs/zh/plugins/split-chunks-plugin#splitchunksminremainingsize)，避免拆分后留下过小的 chunk，进一步对齐 webpack 的产物行为。

例如，部分异步 CSS 导入现在能够保留预期的 `controls.css` 文件名。该选项在开发模式下默认为 `0`，其他模式下回退到 `minSize`。

> 性能与体积数据待补充：chunk 拆分耗时、重复模块数，以及 JS/CSS 压缩前后的体积对比。

### 内存占用优化 \{#memory-improvements}

#### 降低源码映射的内存开销 \{#source-map-memory}

降低了开启 Source Map 时的内存占用，改善大型项目构建和插件读取源码时的内存表现，无需额外配置。

#### 改善大型项目的内存表现 \{#module-memory}

减少大型项目构建时的内存占用，并改善开发服务器反复启动、重建和关闭时的内存释放。

> 内存数据待补充：构建峰值、构建完成后及多轮 HMR 后的内存占用对比。

## 新特性 \{#features}

### 按代码内容过滤 loader \{#loader-code-filter}

新增的 [`module.rules[].use.filter.code`](https://rspack.rs/zh/config/module-rules#rulesusefiltercode) 支持按代码内容跳过不需要的 loader 转换。例如，只对包含 `customMacro()` 调用的文件执行转换：

```js title="rspack.config.mjs"
export default {
  module: {
    rules: [
      {
        test: /\.[cm]?[jt]sx?$/,
        use: [
          {
            loader: './custom-macro-loader.js',
            filter: {
              code: /\bcustomMacro\s*\(/,
            },
          },
        ],
      },
    ],
  },
};
```

`code` 支持字符串和正则表达式，匹配当前 loader 收到的代码。pitch 函数不受影响。

### CSS 打包能力 \{#css-bundling}

#### 独立构建样式入口 \{#css-entry}

纯 CSS 入口现在可以只生成样式文件，适合独立发布主题或样式库：

```js title="rspack.config.mjs"
export default {
  entry: {
    styles: './src/styles.css',
  },
  module: {
    rules: [{ test: /\.css$/i, type: 'css/auto' }],
  },
  output: {
    cssFilename: '[name].css',
  },
};
```

该配置会输出 `styles.css`，不再生成多余的 `styles.js`。

#### 保留外部样式和资源引用 \{#css-externals}

新增 `css-import` 和 `asset-url` 类型的 external，支持保留外部样式和 CDN 资源引用。

CSS 的 `@import`、`url()` 和 `image-set()` 也支持 `rspackIgnore` 和 `webpackIgnore` 注释，可以按需跳过资源打包：

```css title="styles.css"
@import /* rspackIgnore: true */ url('./runtime-theme.css');
```

#### 改进样式兼容性 \{#css-compatibility}

改进内置 CSS Modules 对作用域、组合声明、值引用和嵌套选择器的支持，减少与 webpack css-loader 的行为差异。同时修复了异步样式加载和相对 `publicPath` 的处理。

### 依赖解析与按需编译 \{#resolution-and-lazy-compilation}

#### 更灵活的资源路径处理 \{#resource-resolution}

新增 [`module.parser.javascript.dynamicUrl`](https://rspack.rs/zh/config/module-parser#javascriptdynamicurl)。设置为 `false` 时，动态 `new URL()` 路径会在运行时求值，静态 URL 仍然参与打包，适合由服务端或 CDN 提供动态资源的场景。

此外，`import.meta.glob` 支持解析 pattern 中的路径别名，tsconfig 解析也改善了相对路径和软链接场景的兼容性。

#### 更可靠的懒编译和异步模块 \{#lazy-compilation}

[懒编译](https://rspack.rs/zh/guide/advanced/lazy-compilation)改善了模块首次加载与后续重建的行为，避免已激活模块重复加载，并修复导入属性和路径解析相关的兼容性问题。

嵌套异步导入、延迟导入和 HMR 的兼容性也得到改善。

### Watcher 兼容性改进 \{#watcher-compatibility}

[`experiments.nativeWatcher`](https://rspack.rs/zh/config/experiments#experimentsnativewatcher) 提供了更完整的文件时间信息，改善与 `ts-loader`、`webpack-virtual-modules`、`vue-loader` 等工具的兼容性。

原生 watcher 还支持函数形式的 [`watchOptions.ignored`](https://rspack.rs/zh/config/watch#watchoptionsignored)，并改善了新增目录、文件删除和重新创建时的变化检测。

### 定位内存占用来源 \{#memory-diagnostics}

新增内存分析能力，帮助定位构建和 HMR 期间的内存占用来源，排查内存持续增长的问题。使用方法请参考[内存诊断指南](https://rspack.rs/zh/guide/diagnostics/memory)。

### 插件与工具集成 \{#plugin-integration}

面向插件和 loader 作者，新增或完善了以下能力：

- 通过 [`NormalModuleFactory`](https://rspack.rs/zh/api/plugin-api/normal-module-factory-hooks) 的 `ResolveData.attributes` 读取导入属性。
- 通过 `JavascriptModulesPlugin.getChunkFilenameTemplate()` 查询 chunk 的文件名模板。
- 并行 loader 支持读写 `this._module.buildInfo` 的自定义字段。
- 改善插件 hook 的 webpack 兼容性，并完善 loader、externals 和 stats 的 TypeScript 类型。

### 其他改进 \{#other-improvements}

- **WebAssembly**：新增 [`output.wasmStreamingFallback`](https://rspack.rs/zh/config/output#outputwasmstreamingfallback)，支持关闭非流式加载回退。
- **模块产物**：改善 CommonJS、ESM 和延迟导入的兼容性。
- **构建与缓存**：改善构建失败后的恢复，以及 Windows 上的缓存使用体验。
- **HTTP 导入**：[`experiments.buildHttp`](https://rspack.rs/zh/config/experiments#experimentsbuildhttp) 加强冻结构建中的资源完整性校验。
- **模块联邦**：修复共享模块和 manifest 相关问题。
- **CLI**：减少默认日志，优化启动体验，`create-rspack` 会显示当前版本。
- **React Compiler**：修复处理长表达式时的崩溃问题；HTML 压缩也会保留相邻脚本各自的执行边界。

完整改动可查看 [2.2.0 至当前版本的对比](https://github.com/web-infra-dev/rspack/compare/v2.2.0...v2.3.0-beta.0)和 [GitHub release notes](https://github.com/web-infra-dev/rspack/releases/tag/v2.3.0-beta.0)。

## 升级指南 \{#upgrade-guide}

直接使用 Rspack CLI 的项目，可以将 `@rspack/core` 和 `@rspack/cli` 一起升级至本次 Beta：

<PackageManagerTabs command="add @rspack/core@2.3.0-beta.0 @rspack/cli@2.3.0-beta.0 -D" />

[`incremental`](https://rspack.rs/zh/config/incremental) 仅在开发模式下生效。需要加速重启后的构建时，请使用持久化缓存。

欢迎试用并通过 [GitHub Issues](https://github.com/web-infra-dev/rspack/issues) 反馈问题。
