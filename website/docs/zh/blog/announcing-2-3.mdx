## SWC Next 解析器 \{#swc-next}

Rspack 2.3 将 JavaScript 解析器迁移至 [SWC Next](https://github.com/swc-project/swc-next)。根据 SWC Next 官方基准，其原生解析器比 SWC 快 [2–4.5 倍](https://github.com/swc-project/swc-next/blob/main/website/docs/docs/guide/benchmark.mdx#rust-parse)。

借助更紧凑的 AST 和内存布局，Rspack 也同步优化了解析与遍历流程。在固定 6 个 workers 下，解析阶段耗时和指令数变化如下：

| 项目      | 解析阶段耗时                   | 指令数                          |
| --------- | ------------------------------ | ------------------------------- |
| three.js  | 23.62 ms → 20.11 ms（−14.9%）  | 205.23 M → 155.07 M（−24.4%）   |
| React 10k | 207.16 ms → 193.86 ms（−6.4%） | 1597.67 M → 1421.29 M（−11.0%） |

## 性能 \{#performance}

### 构建性能优化 \{#build-performance}

在 [react-10k 示例项目](https://github.com/LingyuCoder/rspack-react-10k-benchmark/actions/runs/40302457470) 中，Rspack 2.3.0 的 HMR 和缓存热构建耗时较 2.2.0 降低约 5%。

### SplitChunks 优化 \{#split-chunks}

本轮优化从三个方向减少重复代码和产物体积：

- 新增 [`splitChunks.dedupDepth`](https://rspack.rs/zh/plugins/split-chunks-plugin#splitchunksdedupdepth)，通过两两求交发现更多可提取的共享模块组合。生产模式下默认启用（`depth=1`）。
- 改进 chunk 拆分算法，有效减少跨 chunk 的重复模块。
- 支持 [`splitChunks.minRemainingSize`](https://rspack.rs/zh/plugins/split-chunks-plugin#splitchunksminremainingsize)，避免拆分后留下过小的 chunk，对齐 webpack 的产物行为。

在真实大型项目中，开启 `dedupDepth=1` 后的 Brotli 压缩体积变化如下：

| 项目                    | 优化前   | 优化后   | 节省    | 降幅     |
| ----------------------- | -------- | -------- | ------- | -------- |
| 项目 A（client JS/CSS） | 23.22 MB | 22.67 MB | 550 KB  | **2.4%** |
| 项目 B（client JS/CSS） | 39.97 MB | 36.00 MB | 3.97 MB | **9.9%** |

### 内存占用优化 \{#memory-improvements}

Rspack 2.3 在不牺牲构建性能的前提下，进一步降低了大型项目的内存占用。真实项目的峰值与稳态 RSS 对比如下：

| 场景  | 指标         |     2.2.0 |     2.3.0 | 优化      |
| ----- | ------------ | --------: | --------: | --------- |
| Build | 峰值 RSS     | 28.30 GiB | 20.53 GiB | **27.4%** |
| Build | 构建结束 RSS | 25.32 GiB | 16.07 GiB | **36.5%** |
| Dev   | 启动峰值 RSS | 28.63 GiB | 18.96 GiB | **33.8%** |
| Dev   | 稳态 RSS     | 28.88 GiB | 18.83 GiB | **34.8%** |

此外，Rspack 2.3 还新增了基于 [allocative](https://github.com/facebook/buck2/tree/main/allocative) 的内存快照能力，帮助开发者定位构建过程中的内存热点。若你的项目内存占用较高，可以按照[内存诊断指南](../guide/diagnostics/memory)采集并提交结果，我们会协助分析和优化。

## 实验性缓存改进 \{#cache-improvements}

Rspack 2.3 推出实验性缓存实现 `newCache`，带来更细粒度的构建结果复用、更小的缓存文件和更低的缓存写入开销。

目前该功能默认关闭，可通过 [`experiments.newCache`](https://rspack.rs/zh/config/experiments#experimentsnewcache) 开启：

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
  },
  experiments: {
    newCache: true,
  },
};
```

相比旧实现整体保存和恢复模块图的方式，`newCache` 采用更细粒度的缓存，可以独立复用模块构建、代码生成、source map 和压缩结果，并支持缓存单个 loader 的转换结果。新的存储方式也减少了缓存写入时的临时内存开销。

下面分别是 [React 10k](https://github.com/rspack-contrib/build-tools-performance/tree/main/cases/react-10k) 和一个大型真实项目的新旧缓存对比。

React 10k：

| 指标               |    旧缓存 |  newCache |     变化 |
| ------------------ | --------: | --------: | -------: |
| 冷构建总耗时       |    2.11 s |    1.80 s |   -14.5% |
| 热构建总耗时       |  776.9 ms |  837.2 ms |    +7.8% |
| 冷构建峰值内存     | 926.5 MiB | 781.3 MiB |   -15.7% |
| 热构建峰值内存     | 840.5 MiB | 840.7 MiB | 基本持平 |
| 热构建后的磁盘缓存 | 269.0 MiB |  57.2 MiB |   -78.7% |

大型真实项目：

| 指标               |      旧缓存 |    newCache |   变化 |
| ------------------ | ----------: | ----------: | -----: |
| 冷构建总耗时       |     84.89 s |     83.47 s |  -1.7% |
| 热构建总耗时       |     33.18 s |     35.24 s |  +6.2% |
| 冷构建峰值内存     |   11.55 GiB |    9.69 GiB | -16.1% |
| 热构建峰值内存     |    7.67 GiB |    8.23 GiB |  +7.3% |
| 热构建后的磁盘缓存 | 3895.98 MiB | 1092.08 MiB | -72.0% |

newCache 将缓存体积减少约 75%，降低了缓存写入开销。目前热构建略慢主要来自 `make` 阶段缓存策略的变化：旧实现缓存整个模块图，`newCache` 只缓存模块，需要重新构建模块之间的依赖关系。缓存内容减少带来了额外的建图开销，但基于当前依赖重新建图，也让重构建时模块图的正确性更容易保障。在缓存内容保持不变的其他阶段，`newCache` 则有明显的性能提升。

我们会持续优化热构建性能和内存占用，并计划在后续 minor 版本中用 `newCache` 替换旧实现。

### loader 缓存 \{#loader-cache}

启用 `experiments.newCache` 后，可为 loader 设置 `cache: true`，复用未发生变化的转换结果。缓存已支持 `builtin:swc-loader`，并会在相关依赖变化时失效。

测试使用 babel-loader 模拟约 10000 个模块，开启 loader 缓存后构建耗时显著降低：

| 并行loader | 缓存关闭 | 缓存开启 | 提升     |
| ---------- | -------- | -------- | -------- |
| 关闭       | 63.75 s  | 11.16 s  | **5.7x** |
| 开启       | 28.50 s  | 11.88 s  | **2.4x** |

此外，[`cache.maxMemoryGenerations`](https://rspack.rs/zh/config/cache#maxmemorygenerations) 可以控制缓存条目在内存中的保留周期，在内存占用与磁盘读取之间做取舍。

## 新特性 \{#features}

### 按代码内容过滤 loader \{#loader-code-filter}

新增的 [`module.rules[].use.filter.code`](https://rspack.rs/zh/config/module-rules#rulesusefiltercode) 支持按代码内容跳过不需要的 loader 转换。例如，只对包含 `customMacro()` 调用的文件执行转换：

```js title="rspack.config.mjs"
export default {
  module: {
    rules: [
      {
        test: /\.[cm]?[jt]sx?$/,
        use: [
          {
            loader: './custom-macro-loader.js',
            filter: {
              code: /\bcustomMacro\s*\(/,
            },
          },
        ],
      },
    ],
  },
};
```

`code` 支持字符串和正则表达式，匹配当前 loader 收到的代码。pitch 函数不受影响。

### CSS 打包能力 \{#css-bundling}

本次更新覆盖了更多 CSS 场景，包括 CSS Modules 作用域、组合声明、值引用和嵌套选择器，同时修复了异步样式加载和相对 `publicPath` 的相关问题。

#### 独立构建样式入口 \{#css-entry}

纯 CSS 入口现在可以只生成样式文件，适合独立发布主题或样式库：

```js title="rspack.config.mjs"
export default {
  entry: {
    styles: './src/styles.css',
  },
  module: {
    rules: [{ test: /\.css$/i, type: 'css/auto' }],
  },
  output: {
    cssFilename: '[name].css',
  },
};
```

该配置会输出 `styles.css`，不再生成多余的 `styles.js`。

#### 支持外部资源 \{#css-externals}

新增 `css-import` 和 `asset-url` 类型的 external，允许在 CSS 中将指定的样式或资源引用保留为外部资源，不参与打包。

```js title="rspack.config.js"
module.exports = {
  externals: {
    'normalize.css': `${CSS_IMPORT}normalize.css`,
    'https://cdn.example.com/theme.css': `${CSS_IMPORT}https://cdn.example.com/theme.css`,
  },
};
```

上述配置会让 CSS 中的 `@import "normalize.css"` 和 CDN 路径引用直接保留在产物中，由浏览器在运行时自行加载。

CSS 的 `@import`、`url()` 和 `image-set()` 也支持 `rspackIgnore` 和 `webpackIgnore` 注释，可以按需跳过资源打包：

```css title="styles.css"
@import /* rspackIgnore: true */ url('./runtime-theme.css');
```

### 依赖解析与按需编译 \{#resolution-and-lazy-compilation}

#### 更灵活的资源路径处理 \{#resource-resolution}

新增 [`module.parser.javascript.dynamicUrl`](https://rspack.rs/zh/config/module-parser#javascriptdynamicurl)。设置为 `false` 时，动态 `new URL()` 路径会在运行时求值，静态 URL 仍然参与打包，适合由服务端或 CDN 提供动态资源的场景。

此外，`import.meta.glob` 支持解析 pattern 中的路径别名，tsconfig 解析也改善了相对路径和软链接场景的兼容性。

#### 更可靠的懒编译和异步模块 \{#lazy-compilation}

[懒编译](https://rspack.rs/zh/guide/advanced/lazy-compilation)改善了模块首次加载与后续重建的行为，避免已激活模块重复加载，并修复导入属性和路径解析相关的兼容性问题。

嵌套异步导入、延迟导入和 HMR 的兼容性也得到改善。

### Watcher 兼容性改进 \{#watcher-compatibility}

[`experiments.nativeWatcher`](https://rspack.rs/zh/config/experiments#experimentsnativewatcher) 提供了更完整的文件时间信息，改善与 `ts-loader`、`webpack-virtual-modules`、`vue-loader` 等工具的兼容性。

原生 watcher 还支持函数形式的 [`watchOptions.ignored`](https://rspack.rs/zh/config/watch#watchoptionsignored)，并改善了新增目录、文件删除和重新创建时的变化检测。

### 插件与工具集成 \{#plugin-integration}

面向插件和 loader 作者，新增或完善了以下能力：

- 通过 [`NormalModuleFactory`](https://rspack.rs/zh/api/plugin-api/normal-module-factory-hooks) 的 `ResolveData.attributes` 读取导入属性。
- 通过 `JavascriptModulesPlugin.getChunkFilenameTemplate()` 查询 chunk 的文件名模板。
- 并行 loader 支持读写 `this._module.buildInfo` 的自定义字段。
- 改善插件 hook 的 webpack 兼容性，并完善 loader、externals 和 stats 的 TypeScript 类型。

### 其他改进 \{#other-improvements}

- **WebAssembly**：新增 [`output.wasmStreamingFallback`](https://rspack.rs/zh/config/output#outputwasmstreamingfallback)，支持关闭非流式加载回退。
- **模块产物**：改善 CommonJS、ESM 和延迟导入的兼容性。
- **构建与缓存**：改善构建失败后的恢复，以及 Windows 上的缓存使用体验。
- **HTTP 导入**：[`experiments.buildHttp`](https://rspack.rs/zh/config/experiments#experimentsbuildhttp) 加强冻结构建中的资源完整性校验。
- **模块联邦**：修复共享模块和 manifest 相关问题。
- **CLI**：减少默认日志，优化启动体验，`create-rspack` 会显示当前版本。
- **React Compiler**：修复处理长表达式时的崩溃问题；HTML 压缩也会保留相邻脚本各自的执行边界。

完整改动可查看 [2.2.0 至当前版本的对比](https://github.com/web-infra-dev/rspack/compare/v2.2.0...v2.3.0)和 [GitHub release notes](https://github.com/web-infra-dev/rspack/releases/tag/v2.3.0)。

## 生态 \{#ecosystem}

### Rsbuild \{#rsbuild}

Rsbuild 2.3 已与 Rspack 2.3 同步发布。

#### 默认启用 compact-hashed ID \{#rsbuild-compact-hashed}

Rsbuild 生产环境现在默认启用 `compact-hashed` 模块和 chunk ID 策略，相比 `deterministic` 可进一步缩小产物体积（约 0.3% JS 体积，约 0.9% gzip）。2.3 修复了 chunk 名称冲突和 hash key 前缀耗尽等边界场景。

#### 文件体积报告增强 \{#rsbuild-stats}

持续优化统计开销，增强体积报告能力：

- 支持 Brotli 体积统计，可配置 gzip / Brotli 的压缩等级。
- 压缩统计不再缓存完整压缩结果，减少内存占用。
- 限制多环境之间的压缩并发，复用资源 Buffer，减少额外读取和复制。
- 在 emit 阶段计算体积，修正统计时机；只显示总计时，也能正确显示压缩体积差值。

#### TanStack Start 模板 \{#rsbuild-tanstack-start}

`create-rsbuild` 新增 [TanStack Start](https://tanstack.com/start) 模板，同时支持 React 和 Solid 两种变体：

```bash
npx -y create-rsbuild@latest my-app -t tanstack-start-ts
```

#### Lynx 框架支持 \{#rsbuild-lynx}

新增 [Lynx](https://lynxjs.org/) 框架选项，支持构建 Lynx 跨平台应用。

```js title="rsbuild.config.ts"
export default {
  environments: {
    lynx: {
      output: {
        target: 'lynx',
      },
    },
  },
};
```

### Rslib \{#rslib}

#### Rslib 1.0 正式发布 \{#rslib-v1}

Rslib 1.0 已正式发布，查看 [Rslib 1.0 博客](https://rslib.rs/zh/blog/v1-0) 了解更多。

#### 内联 Wasm 模块 \{#rslib-inline-wasm}

Rslib 现在支持通过 `?inline` 将 Wasm 二进制内联到 JavaScript 产物中，无需额外分发和加载 `.wasm` 文件：

```js
import { add } from './add.wasm?inline';

console.log(add(1, 2));
```

> 更多用法参考 [Wasm 指南](https://rslib.rs/zh/guide/advanced/wasm)。

#### 支持 TypeScript 7.1 \{#typescript-7-1}

Rslib 1.0.4 支持使用 TypeScript 7.1 Beta 生成类型，并支持通过 [Content Mappers](https://devblogs.microsoft.com/typescript/announcing-typescript-7-1-beta/#content-mappers) 扩展组件文件的类型支持。

你可以安装 TypeScript 7.1 Beta 来体验：

### Rsdoctor \{#rsdoctor}

[Rsdoctor 2.0](https://rsdoctor.rs/zh/blog/release/release-note-2_0) 正式发布！新版本推荐使用 Agent CLI 进行 AI 辅助分析，可直接读取构建数据并输出结构化结果。
同时增强了 Rspack 分析能力，支持多 Compiler 报告，安装体积减少 56%、分析耗时降低 57%，开发模式下的 HMR 耗时降低约 47%。

### Rstest \{#rstest}

[Rstest 0.12](https://rstest.rs/blog/announcing-0-12) 重新设计了 JavaScript API，并新增截图测试能力 —— 通过 `toMatchScreenshot()` 对元素和页面进行视觉断言：

```ts
import { expect, test } from '@rstest/core';

test('home page', async ({ page }) => {
  await page.goto('/');
  await expect(page).toMatchScreenshot('home.png');
});
```

独立的 [VS Code 扩展](https://marketplace.visualstudio.com/items?itemName=rstest.rstest-vscode) 也已发布，提供测试发现、运行和调试的内置体验。

### Rspress \{#rspress}

Rspress 2.1.0 默认支持 [WebMCP](https://developer.chrome.com/docs/ai/webmcp)，内置站点信息查询、文档搜索和页面导航等工具，让浏览器中的 Agent 能够直接与文档站点交互。

想尝试该功能？在支持 WebMCP 的浏览器中，运行以下代码：

```js
const tools = await document.modelContext.getTools();
const tool = tools.find(({ name }) => name === 'rspress_get_current_page');
const page = JSON.parse(await document.modelContext.executeTool(tool, {}));
console.log(page.markdown);
```

你也可以通过 `useWebMcp` Hook 注册自定义工具，扩展站点与 Agent 的交互能力。

更多内容请参阅 [WebMCP 文档](https://rspress.rs/zh/guide/basic/webmcp)。
