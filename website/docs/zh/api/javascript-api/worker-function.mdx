# workerFunction

`workerFunction` 用于描述独立模块导出的函数，让 Rust 将受支持的 hook 和 splitChunks 名称回调直接分派到与并行 loader 共用的 worker 池。

```ts
function workerFunction<Fn extends Function>(target: string, options: any): Fn;
```

首个支持的 hook 是 `NormalModuleFactory.beforeResolve.tapPromise`：

```js title="rspack.config.cjs"
const path = require('node:path');
const { workerFunction } = require('@rspack/core');

module.exports = {
  plugins: [
    {
      apply(compiler) {
        compiler.hooks.normalModuleFactory.tap('RewriteRequests', (factory) => {
          factory.hooks.beforeResolve.tapPromise(
            'RewriteRequests',
            workerFunction(path.join(__dirname, 'rewrite.cjs'), {
              from: 'virtual-entry',
              to: './src/index.js',
            }),
          );
        });
      },
    },
  ],
};
```

```js title="rewrite.cjs"
module.exports = async function (resolveData, options) {
  if (resolveData.request === options.from) {
    resolveData.request = options.to;
  }
};
```

目标模块必须导出 CJS 函数或 ESM default 函数。调用时，`options` 追加在 hook 参数末尾。`beforeResolve` 返回 `undefined` 表示继续，返回 `false` 表示忽略请求。受支持的 resolveData 字段和依赖数组的修改会写回 Rust。参数是数据快照，保留它不会保留原生 compiler 对象的访问能力。

相对路径以 `compiler.context` 为基准解析，包名和 alias 使用 `resolveLoader` 配置。推荐用绝对路径引用配置文件旁的模块。目标不支持 loader query、fragment、builtin loader 标识或 `pitch`、`raw` 等 loader 导出约定。

普通 tap 和 worker tap 保留排序后的执行顺序，包括 `stage` 和 `before`。在原生 Node.js 中加载 Rspack 时，会提前启动 workerFunction 和 parallel loader 共用的 worker 池。使用这些 worker 的 compiler 会在开始 native build 前等待就绪，普通构建不会等待。空闲 worker 不会阻止进程退出。在导入 Rspack 前设置 `RSPACK_LOADER_WORKER_THREADS` 可控制预启动的池大小；首次使用池时仍可通过 loader 的 `parallel.maxWorkers` 指定数量。模块状态属于各自 worker，不保证连续调用会分配到同一个 worker；每次调用的状态应放在参数中。

## splitChunks 名称

`optimization.splitChunks.name` 和 `optimization.splitChunks.cacheGroups.*.name` 都支持 `workerFunction`：

```js title="rspack.config.cjs"
const { workerFunction } = require('@rspack/core');

module.exports = {
  optimization: {
    splitChunks: {
      chunks: 'all',
      name: workerFunction('./chunk-name.cjs', { prefix: 'shared' }),
    },
  },
};
```

```js title="chunk-name.cjs"
module.exports = (module, chunks, cacheGroupKey, options) =>
  `${options.prefix}-${cacheGroupKey}-${chunks.map((chunk) => chunk.name ?? 'unnamed').join('-')}`;
```

函数可以同步或通过 Promise 返回字符串或 `undefined`。其他返回值及 worker 错误会使构建失败。Rust 将每次命名调用直接派发到共享的原生 worker 队列。

参数是冻结的独立快照，仅支持 `module.identifier()`、`module.nameForCondition()`、`module.type`、`module.layer` 和 `chunks[].name`。缺失的 condition name、layer 和 chunk 名称为 `undefined`。worker 无法访问原生 Module/Chunk 的其他方法或 compilation graph。可以安全保留快照，快照无法修改编译状态。普通名称回调仍使用原有的 Module 和 Chunk 对象。模块状态在每个 worker 中独立存在；调用顺序及 worker 分配不固定，命名函数应返回确定的结果。

## Loader hooks

`NormalModule.getCompilationHooks(compilation).loader.tap` 支持同步的 `workerFunction`，目标模块接收 `(loaderContext, module, options)`。内置 `CssExtractRspackPlugin` 使用它初始化 loader context。

对于并行 loader，如果当前 compilation 及其父 compilation 的所有 loader tap 都是 worker function，且没有 interceptor，Rspack 会在执行 loader 的同一个 worker 中先运行这些 taps。普通 loader 在本地执行这些函数。如果 hook 链中包含普通 tap 或 interceptor，整条链会在主线程执行，以保持同步调用顺序及 context 修改的可见性；随后将可传输的 context 扩展字段（包括 `Symbol.for` 属性）传给并行 loader。

回调必须同步完成。Loader context 和 module 遵循并行 loader API 及生命周期限制，不应在回调结束后保留它们，也不应假设 worker 拥有主线程 compiler 的 JavaScript 状态。

## Options 中的函数

Options 支持可传输数据、循环引用、`Map`、`Set` 及嵌套的 `workerFunction`。嵌套函数在使用 options 的 isolate 内执行。ESM 模块会在进入用户代码前准备完成，因此读取 loader options 仍然是同步操作：

```js
{
  loader: require.resolve('./transform.cjs'),
  parallel: true,
  options: {
    transform: workerFunction(require.resolve('./transform-value.cjs'), { prefix: 'hello' }),
  },
}
```

Loader 可以调用 `this.getOptions().transform(value)`。普通 loader 在主线程执行恢复后的函数，并行 loader 在自己的 worker 中执行。同一模块搭配不同 options 会生成不同的绑定函数。普通函数保留 loader 现有的函数 RPC 行为，包括同步返回的限制，不会自动搬运闭包。

## 支持环境与限制

原生调度需要 Node.js worker，暂不支持 browser 和 WASI。其他 hook、`tapAsync`、HookMap 中的 worker 注册会明确报错。`beforeResolve` 只支持 `tapPromise`，不支持 JavaScript hook interceptor。Loader hook 只支持同步 `tap`，并按上述规则回退到主线程执行。

工厂返回的是用于 Rspack 注册和数据准备的带标记占位符，请勿直接调用。泛型 `Fn` 只描述暴露的签名，运行时仍会校验描述符和模块导出。失败或被中断的 worker 任务会使构建报错，不会自动重试用户函数。
