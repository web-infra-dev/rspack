# Stats

`Stats` 对象提供一次构建的统计信息，包括错误、警告、构建耗时，以及输出资源、模块和 chunk 的信息。你可以在构建脚本或插件中通过它判断构建是否成功、打印构建摘要，或为分析工具提供数据。

它提供了以下常用方法：

- [`hasErrors()`](#haserrors) 和 [`hasWarnings()`](#haswarnings)：判断构建是否存在错误或警告。
- [`toJson()`](#tojson)：以 JavaScript 对象的形式返回所需的构建信息，便于进一步处理或交给分析工具。
- [`toString()`](#tostring)：将所需的构建信息格式化为文本，便于在控制台输出。

## 获取 Stats \{#getting-stats}

调用 [`rspack()`](/api/javascript-api/#rspack) 执行构建时，可以通过回调函数的第二个参数获取 `Stats` 对象。下面的脚本会打印构建中的错误和警告，并在构建失败时设置非零退出码：

```js title="build.mjs"
import { rspack } from '@rspack/core';
import config from './rspack.config.mjs';

rspack(config, (err, stats) => {
  if (err) {
    console.error(err);
    process.exitCode = 1;
    return;
  }

  console.log(stats.toString('errors-warnings'));

  if (stats.hasErrors()) {
    process.exitCode = 1;
  }
});
```

回调中的 `err` 用于报告导致 Rspack 无法完成构建的错误。找不到模块、语法错误等编译错误则记录在 `stats` 中，因此即使 `err` 为空，也需要通过 `stats.hasErrors()` 判断构建是否成功。

你也可以通过以下方式获取 Stats：

- **使用 Compiler 实例**：从 [`compiler.run()`](/api/javascript-api/compiler#run) 或 [`compiler.watch()`](/api/javascript-api/compiler#watch) 回调函数的第二个参数获取 Stats。watch 模式下，每次构建完成都会返回本次构建的结果。
- **编写插件**：在 [`compiler.hooks.done`](/api/plugin-api/compiler-hooks#done) 的回调中获取编译完成后的 Stats。
- **已有 Compilation 对象**：调用 [`compilation.getStats()`](/api/javascript-api/compilation#getstats) 获取对应的 Stats。生成输出前，请留意[调用时机](#call-timing)。

如果向 `rspack()` 传入配置数组，回调接收到的则是 [`MultiStats`](#multistats) 对象，其中包含各个配置对应的构建结果。

## Stats 方法

### hasErrors

用来检查编译期是否有错误。

**类型：**

```ts
hasErrors(): boolean;
```

可以根据返回值处理编译错误：

```js
if (stats.hasErrors()) {
  console.error('编译失败');
}
```

### hasWarnings

用来检查编译期是否有警告。

**类型：**

```ts
hasWarnings(): boolean;
```

可以根据返回值处理编译警告：

```js
if (stats.hasWarnings()) {
  console.warn('编译完成，但存在警告');
}
```

### toJson

以 [Stats JSON](/api/javascript-api/stats-json) 对象形式返回编译信息。可以传入[预设名称或配置对象](/config/stats)，选择要包含的信息。

使用时请留意[调用时机](#call-timing)和[性能开销](#performance-overhead)。

`assets` 数组中各对象的结构和字段说明见 [Asset 对象结构](/api/javascript-api/stats-json#asset-object)。

**类型：**

```ts
toJson(options?: StatsValue): StatsCompilation;
```

使用 `'minimal'` 预设并打印错误数量：

```js
const statsJson = stats.toJson('minimal');
console.log(statsJson.errorsCount);
```

也可以通过配置对象选择要输出的字段，然后打印编译哈希：

```js
const statsJson = stats.toJson({
  all: false,
  hash: true,
});
console.log(statsJson.hash);
```

### toString

以格式化的字符串形式返回描述编译信息（类似 [CLI](/api/cli) 的输出）。

使用时请留意[调用时机](#call-timing)和[性能开销](#performance-overhead)。

**类型：**

```ts
toString(opts?: StatsValue): string;
```

可以通过 [Stats 配置](/config/stats) 控制输出内容，也可以通过 `colors` 控制文字颜色：

```js
stats.toString({
  // 增加控制台颜色开关
  colors: true,
});
```

下面是 `stats.toString()` 用法的示例：

```js
import { rspack } from '@rspack/core';

rspack(
  {
    // ...
  },
  (err, stats) => {
    if (err) {
      console.error(err);
      return;
    }

    console.log(
      stats.toString({
        chunks: false, // 使构建过程更静默无输出
        colors: true, // 在控制台展示颜色
      }),
    );
  },
);
```

### hash

**类型：** `string | null`

获取此次构建的哈希值，等同于 [`Compilation.hash`](/api/javascript-api/compilation#hashfullhash)。

将其作为字符串使用前，先检查是否为 `null`：

```js
if (stats.hash !== null) {
  console.log(stats.hash);
}
```

## 注意事项 \{#usage-notes}

### 调用时机 \{#call-timing}

`stats.toJson()` 和 `stats.toString()` 依赖在 `compiler.hooks.done` 阶段才最终稳定的编译产物。如果在其他时机调用（例如复用更早阶段拿到的旧 `Stats` 对象），部分 Stats 字段可能不完整。

为了拿到完整且稳定的 Stats 输出，建议在 `compiler.hooks.done` 中调用这些方法：

```js
compiler.hooks.done.tap('MyPlugin', (stats) => {
  const statsJson = stats.toJson({ all: false, errors: true, warnings: true });
  const statsText = stats.toString({ preset: 'errors-warnings' });
  console.log(statsJson.errors);
  console.log(statsText);
});
```

### 性能开销 \{#performance-overhead}

`stats.toJson()` 和 `stats.toString()` 会从 Rust 收集编译数据，并在 JavaScript 中处理。开启 [`all: true`](/config/stats#statsall) 可能显著增加数据传输量和 Stats 生成耗时，尤其是在大型项目中。模块源码、模块引用原因和 chunk 中的模块等详细信息应按需开启。

建议传入 `all: false`，只开启代码实际使用的字段。这些选项需要直接传给 `toJson()` 或 `toString()`，它们不会自动继承顶层 `stats` 配置。例如，读取错误和警告的详细信息：

```js
const statsJson = stats.toJson({
  all: false,
  errors: true,
  warnings: true,
});
```

同一次构建中，如果需要多次使用相同的统计信息，应复用生成的结果，避免重复调用带来的开销。

## MultiStats

当使用 [`MultiCompiler`](/api/javascript-api/compiler#multicompiler) 执行多个编译任务时，编译结果会被包装为一个 `MultiStats` 对象。它提供合并后的哈希，以及用于检查、序列化和格式化所有子编译结果的方法。

### hash

<Badge text="只读" type="info" />

**类型：** `string`

获取由所有子编译哈希依次拼接而成的字符串。

打印拼接后的哈希：

```js
console.log(multiStats.hash);
```

### hasErrors

任一子编译存在错误时返回 `true`。

**类型：**

```ts
hasErrors(): boolean;
```

可以根据返回值处理所有子编译中的错误：

```js
if (multiStats.hasErrors()) {
  console.error('至少一个编译失败');
}
```

### hasWarnings

任一子编译存在警告时返回 `true`。

**类型：**

```ts
hasWarnings(): boolean;
```

可以根据返回值处理所有子编译中的警告：

```js
if (multiStats.hasWarnings()) {
  console.warn('至少一个编译存在警告');
}
```

### toJson

返回一个 `StatsCompilation`，其 `children` 数组包含每个子编译的 [Stats JSON](/api/javascript-api/stats-json)。对所有子编译均启用的字段（如 `errors` 和 `warnings`）还会汇总到顶层。

**类型：**

```ts
toJson(options: boolean | StatsPresets | MultiStatsOptions): StatsCompilation;
```

为所有子编译使用同一个预设，并查看结果数量：

```js
const statsJson = multiStats.toJson('minimal');
console.log(statsJson.children?.length);
```

`MultiStatsOptions` 还支持通过 `children` 选项分别配置每个子编译。以下示例打印第一个子编译的错误信息：

```js
const statsJson = multiStats.toJson({
  children: [
    { all: false, errors: true },
    { all: false, assets: true },
  ],
});
console.log(statsJson.children?.[0]?.errors);
```

### toString

根据 [Stats 配置](/config/stats) 格式化每个子编译，再将结果拼接成一个字符串。

**类型：**

```ts
toString(options: boolean | StatsPresets | MultiStatsOptions): string;
```

为所有子编译使用同一个预设，并打印合并后的输出：

```js
const statsText = multiStats.toString('minimal');
console.log(statsText);
```

## Stats factory

`StatsFactory` 从 Compilation 生成 Stats JSON，并提供钩子来定制生成的内容。输出文本时，`StatsPrinter` 会进一步将 Stats JSON 格式化为字符串。它们与 `stats.toJson()`、`stats.toString()` 的关系如下：

```txt title=Stats 输出
Compilation ===============> Stats JSON =================> Stats Output
           ╰─ StatsFactory ─╯           ╰─ StatsPrinter ─╯
╰─────────── stats.toJson() ───────────╯
╰───────────────────────── stats.toString() ──────────────────────────╯
```

可通过 [`compilation.hooks.statsFactory`](/api/plugin-api/compilation-hooks#statsfactory) 获取。或者通过 `new StatsFactory()` 创建新实例。

### Hooks

详见 [StatsFactory 钩子](/api/plugin-api/stats-hooks#statsfactory)

### create

`StatsFactory` 的核心方法，根据 `type` 指定当前数据结构，查找并运行对应的生成器以生成 Stats 项目。

```ts
stats = statsFactory.create('compilation', compilation, {});
```

> `StatsFactory` 对象仅负责处理调用钩子，对应类型的处理代码的处理代码可在 [`DefaultStatsFactoryPlugin`](https://github.com/web-infra-dev/rspack/blob/main/packages/rspack/src/stats/DefaultStatsFactoryPlugin.ts) 中找到。

## Stats printer

用于从 Stats JSON 对象生成输出字符串，并且提供了钩子以在生成过程中进行细粒度的控制。

可通过 [`compilation.hooks.statsPrinter`](/api/plugin-api/compilation-hooks#statsprinter) 获取。或者通过 `new StatsPrinter()` 创建新实例。

### Hooks

详见 [StatsPrinter 钩子](/api/plugin-api/stats-hooks#statsprinter)

### print

`StatsPrinter` 的核心方法，根据 `type` 指定当前数据结构，查找并运行对应的生成器以生成 Stats 项目的输出字符串。

```ts
stats = statsPrinter.print('compilation', stats, {});
```

> `StatsPrinter` 对象仅负责处理调用钩子，对应类型的处理代码的处理代码可在 [`DefaultStatsPrinterPlugin`](https://github.com/web-infra-dev/rspack/blob/main/packages/rspack/src/stats/DefaultStatsPrinterPlugin.ts) 中找到。
