## 更新保留的入口导出

Rspack 插件可以通过 `additionalTreeRuntimeRequirements` 请求
`compiler.webpack.RuntimeGlobals.updateEntryExports`，生成以下运行时函数：

```ts
updateEntryExports(entryModuleId: string | number, nextExports: unknown): boolean;
```

当模块 ID 匹配当前 runtime chunk 默认启动流程的最后一个入口模块时，该函数替换
bootstrap 保留的启动导出并返回 `true`。其他模块 ID、没有入口的共享 runtime chunk，
以及自定义启动流程（`startupNoDefault`）均返回 `false`，不修改导出。
调用方必须在不支持同步时回退到应用重建。

这是 Rspack 为实现入口重载的插件提供的专有能力。它不执行模块、不清除模块缓存、
不更新已发布的 library 导出，也不释放业务持有的引用。调用方需要先重载入口，
并单独发布新的导出，重载的应是同一份编译后的入口。

对于导出名称在构建时已知的同步 ESM 入口，`commonjs2` 和 `commonjs-module` 输出会发布
一个稳定的命名空间，其 getter 跟随启动导出。这样 Node 私有的首次导出快照便不会保留
旧入口的导出。命名空间保持编译时的导出名称，不支持通过此 API 改变其结构。
其他 library 输出以及异步或动态导出结构保持原有发布行为，需要调用方自行处理引用。

请求此能力会禁用入口内联；未请求此能力的构建不受影响。
