# Extends

使用 `extends` 可以让多个项目共用一份基础配置，也可以在开发构建和生产构建之间复用配置。例如，开发和生产配置可以继承相同的 loader 和插件，再分别设置 `mode` 和 `devtool`。

- **类型：** `string | string[]`
- **默认值：** `undefined`

`extends` 仅在 [`@rspack/cli`](/api/cli) 中生效。如果你使用 JavaScript API 或其他基于 Rspack 的工具，可以用 [rspack-merge](/config#rspack-merge) 合并配置。

## 基本用法

将 `extends` 设为基础配置文件的路径，可以是绝对路径，也可以是相对路径。相对路径以声明 `extends` 的文件所在目录为准。基础配置也支持 JSON 格式，例如 `./base.rspack.config.json`。

<Tabs>
  <Tab label="ESM">

```js title="rspack.config.mjs"
export default {
  extends: './base.rspack.config.mjs',
  output: {
    filename: '[name].bundle.js',
  },
};
```

  </Tab>
  <Tab label="CJS">

```js title="rspack.config.cjs"
module.exports = {
  extends: './base.rspack.config.cjs',
  output: {
    filename: '[name].bundle.js',
  },
};
```

  </Tab>
</Tabs>

## 多个配置

要继承多个配置，可以把它们列在 `extends` 数组中。CLI 使用 [rspack-merge](https://github.com/rstackjs/rspack-merge) 从右往左合并这些配置，最后合并当前配置。

```js title="rspack.config.mjs"
export default {
  extends: ['./dev.config.mjs', './web.config.mjs'],
  output: {
    filename: '[name].js',
  },
};
```

上例的合并顺序是 `web.config.mjs`、`dev.config.mjs`、`rspack.config.mjs`。

- **简单值**会被后合并的值覆盖。如果两个基础配置都设置了 `mode`，就采用 `dev.config.mjs` 的值。如果当前配置也设置了 `mode`，则以当前配置为准。
- **对象**按属性递归合并。上例覆盖了 `output.filename`，同时保留了从基础配置继承的其他属性，如 `output.publicPath`。
- **数组**按合并顺序拼接。例如，合并后的 `plugins` 数组中，`web.config.mjs` 的插件排在最前，接下来是 `dev.config.mjs` 的插件，最后是当前配置的插件。`module.rules` 也遵循这个顺序。

## Node 模块

如果已安装的 npm 包导出了 Rspack 配置，可以直接用包名继承这份配置。

```js title="rspack.config.mjs"
export default {
  extends: 'some-rspack-config-package',
};
```

## 嵌套扩展

基础配置也可以继承其他配置。例如，上例中的 `dev.config.mjs` 可以继承通用配置，再设置开发模式。

```js title="dev.config.mjs"
export default {
  extends: './shared.mjs',
  mode: 'development',
};
```

如果 `web.config.mjs` 也继承了 `shared.mjs`，合并时两份配置都会带上 `shared.mjs` 中的插件，同一个插件就会注册两次。只需注册一次的插件可以从 `shared.mjs` 移到 `rspack.config.mjs`。

如果一个文件直接或间接继承自身，CLI 会列出构成循环的文件。例如，`Circular extends chain: dev.config.mjs -> shared.mjs -> dev.config.mjs` 表示这两个文件互相继承。移除其中一处 `extends` 引用即可打破循环。
