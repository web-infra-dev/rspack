# Extends

使用 `extends` 可以在多个项目或环境之间复用 Rspack 配置。把通用选项放在基础配置中，再在当前配置中覆盖需要调整的选项。

- **类型：** `string | string[]`
- **默认值：** `undefined`

`extends` 仅在 [`@rspack/cli`](/api/cli) 中生效。如果使用 JavaScript API，可以通过 [rspack-merge](/config#rspack-merge) 手动合并配置。

## 基本用法

将 `extends` 设为配置文件的路径。可以使用绝对路径。使用相对路径时，以声明 `extends` 的配置文件所在目录为准。基础配置也可以是 JSON 文件，例如 `./base.rspack.config.json`。

<Tabs>
  <Tab label="ESM">

```js title="rspack.config.mjs"
export default {
  extends: './base.rspack.config.mjs',
  output: {
    filename: '[name].bundle.js',
  },
};
```

  </Tab>
  <Tab label="CJS">

```js title="rspack.config.cjs"
module.exports = {
  extends: './base.rspack.config.cjs',
  output: {
    filename: '[name].bundle.js',
  },
};
```

  </Tab>
</Tabs>

## 多个配置

要继承多个配置，可以将它们写在一个数组中。对于 `mode` 这样的选项，当前配置的值优先。如果当前配置没有设置该选项，则按数组顺序查找，采用第一个找到的值。

```js title="rspack.config.mjs"
export default {
  extends: ['./dev.config.mjs', './web.config.mjs'],
  output: {
    filename: '[name].js',
  },
};
```

如果两个文件都设置了 `mode`，这个例子会使用 `dev.config.mjs` 中的值。对象和数组则按各自的规则合并。

- 对象按属性合并。例子中的 `output.filename` 会覆盖继承的文件名，同时保留基础配置中的 `output.publicPath`。
- `plugins` 和 `module.rules` 等数组会拼接在一起。在这个例子中，`web.config.mjs` 中的插件排在最前面，其次是 `dev.config.mjs` 中的插件，最后是你在 `rspack.config.mjs` 中添加的插件。

## Node 模块

要使用已安装的 npm 包提供的配置，可以将 `extends` 设为包名。该包需要导出一份 Rspack 配置。

```js title="rspack.config.mjs"
export default {
  extends: 'some-rspack-config-package',
};
```

## 嵌套扩展

基础配置也可以使用 `extends`。例如，如果 `dev.config.mjs` 继承了 `./shared.mjs`，CLI 会在 `dev.config.mjs` 所在的目录查找 `shared.mjs`。

如果 `dev.config.mjs` 和 `web.config.mjs` 都继承了 `shared.mjs`，两份配置就会各自继承一份 `shared.mjs` 的设置。这样一来，`shared.mjs` 中注册的插件会执行两次。如果只需要执行一次，可以把插件移到 `rspack.config.mjs` 中注册。

如果 CLI 报错 `Circular extends chain: dev.config.mjs -> shared.mjs -> dev.config.mjs`，说明这两个文件互相继承。删除任意一方对另一方的 `extends` 引用，即可解除循环。
