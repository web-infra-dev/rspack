# Cache

<ApiMeta addedVersion="2.0.0" />

`cache` 选项用于控制 Rspack 的缓存策略，让 Rspack 可以在构建之间复用缓存数据以提升构建性能。

Rspack 支持两种启用状态的 Cache 存储模式：进程内的 Memory Cache，以及基于文件系统的 Persistent Cache。两者都用于存储细粒度计算结果，并且与 [`incremental`](/config/incremental) 相互独立。

:::tip
我们正在开发一套更快更稳定的缓存实现，未来将替换现有实现。如需提前尝试，可以启用 [`experiments.newCache`](/config/experiments#experimentsnewcache)。
:::

- **类型：**

```ts
type CacheOptions =
  | boolean
  | {
      type: 'memory';
    }
  | {
      type: 'persistent';
      name?: string;
      buildDependencies?: string[];
      version?: string;
      maxAge?: number;
      maxMemoryGenerations?: number;
      maxVersions?: number;
      portable?: boolean | { root?: string; rebaseLoaderRequests?: boolean };
      readonly?: boolean;
      snapshot?: {
        immutablePaths?: Array<string | RegExp>;
        unmanagedPaths?: Array<string | RegExp>;
        managedPaths?: Array<string | RegExp>;
      };
      storage?: {
        type: 'filesystem';
        directory?: string;
        location?: string;
      };
    };
```

- **默认值：** development 模式为 `{ type: 'memory' }`（等价于 `true`），production 模式和 none 模式为 `false`

## 与 Incremental 的关系

Cache 和 [`incremental`](/config/incremental) 相互正交。Cache 控制细粒度 Cache entry 的读取和存储；Incremental 控制开发期重建是否恢复上一轮 pass 的 Artifact，并根据已知 mutations 更新受影响的工作。

- `cache: false` 不会关闭 Incremental。
- `incremental: false` 不会关闭 Cache。
- FileSystem Cache 可以加速后续的一次性 build，但这属于 Cache 命中，而不是增量构建。

如果需要同时关闭两种复用机制，应显式设置两个选项：

```js title="rspack.config.mjs"
export default {
  cache: false,
  incremental: false,
};
```

## 内存缓存

将 `cache` 设置为 `true` 或 `{ type: 'memory' }` 可以启用内存缓存。内存缓存只保存在当前 compiler 进程中，主要用于 rebuild、watch 模式和 HMR。

内存缓存不会将缓存数据写入磁盘，因此进程结束后缓存会被清空，也无法加速后续重新启动的全新构建。它更适合开发阶段的长时间运行场景，例如同一个 compiler 实例持续处理多次重建。

```js title="rspack.config.mjs"
export default {
  cache: true,
};
```

或：

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'memory',
  },
};
```

## 持久化缓存

将 `cache` 设置为 `{ type: 'persistent' }` 可以启用基于文件系统的持久化缓存。持久化缓存会将缓存数据写入磁盘，以便后续构建进程复用。

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
  },
};
```

### name

- **类型：** `string`
- **默认值：** 设置 `config.name` 时为 `<config.name>-<mode>`，否则为 `<mode>`

`cache.name` 用于命名持久化缓存。不同的名称会创建可同时存在的缓存。在 multi compiler 模式下，第一个 compiler 保持默认名称，后续 compiler 追加从零开始的 index，例如 `-1`、`-2`。

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
    name: 'client-development',
  },
};
```

### buildDependencies

- **类型：** `string[]`
- **默认值：** `[]`

`cache.buildDependencies` 是构建依赖的文件或目录路径数组。Rspack 会追踪这些路径，并在任意被追踪的构建依赖发生变化时使持久化缓存失效。

```js title="rspack.config.mjs"
import { join } from 'node:path';

export default {
  cache: {
    type: 'persistent',
    buildDependencies: [
      import.meta.filename,
      join(import.meta.dirname, './tsconfig.json'),
    ],
  },
};
```

:::tip
与 webpack 不同，Rspack 默认不预设任何构建依赖。建议将未被 Rspack CLI 加载的项目配置文件添加到 `cache.buildDependencies`，以确保这些文件变化时缓存能及时失效。

注意：使用 Rspack CLI 时，配置文件会自动被添加到 `cache.buildDependencies` 中。

解析构建依赖时，Rspack 会递归遍历目录，并通过 AST 解析 JS/TS 文件以追踪传递依赖。对于解析到 `node_modules` 下的依赖，Rspack 会停止递归解析，并在可用时追踪对应包的 `package.json`。
:::

### version

- **类型：** `string`
- **默认值:** `""`

`cache.version` 用于标识持久化缓存数据的格式。当它与已存储的版本不一致时，Rspack 不会复用现有缓存，并会在构建完成后覆盖其内容。当配置发生不兼容变更时，应更新该值。

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
    version: 'v1',
  },
};
```

:::warning
不要在不同配置之间共享同一份缓存（相同的 `cache.version` 和 `cache.storage.location`），这样可能导致错误的缓存命中。
:::

:::tip 持久化缓存失效

Rspack 会基于 `compilerPath` 的哈希拆分缓存子目录，每个 `compilerPath` 只保留一份缓存。[version](#version) 变化时，Rspack 会使该 compiler 的现有缓存失效并覆盖其内容，不会保留多个版本。

:::

### maxVersions

<ApiMeta stability={Stability.Deprecated} />

- **类型：** `number`
- **默认值：** 未设置

`cache.maxVersions` 仅为向后兼容而保留，但不会产生任何作用。Rspack 对每个 `compilerPath` 只保留一份持久化缓存。显式配置此选项时，Rspack 会输出弃用警告。

### maxMemoryGenerations

- **类型：** `number`（非负整数）或 `Infinity`
- **默认值：** development 模式为 `5`，production 和 none 模式为 `Infinity`

持久化缓存中未使用的条目在额外内存缓存中保留的代数。设置为 `0`
可禁用内存缓存，此后每次需要条目时都会从磁盘读取；设置为 `Infinity`
则会在 compiler 的整个生命周期内将条目保留在内存中。

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
    maxMemoryGenerations: 0,
  },
};
```

### maxAge

- **类型：** `number`（正整数，单位为秒）或 `Infinity`
- **默认值：** `7 * 24 * 60 * 60`（7 天）

一份 compiler 缓存在未被访问后允许保留的最长时间，单位为秒。清理时，Rspack 会删除超过 `maxAge` 时间未被访问的 compiler 缓存目录。设置为 `Infinity` 可禁用基于时间的清理。

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
    maxAge: 7 * 24 * 60 * 60,
  },
};
```

### portable

如需从其他 worktree 初始化独立缓存，请参阅 [`experiments.portableCache`](/config/experiments#experimentsportablecache)。

- **类型：** `boolean | { root?: string; rebaseLoaderRequests?: boolean }`
- **默认值：** `false`

设置为 `true` 或 `{ root }` 可启用可移植路径编码。默认根目录是从 `context`（含自身）向上查找的第一个包含 `.git` 文件或目录的祖先目录；找不到时使用 `context`。使用 Git 顶层目录可以涵盖 monorepo 中的兄弟包和仓库级依赖。显式指定的 `root` 相对于 `context` 解析。根目录保留 `context` 的路径写法，因此通过符号链接访问的项目仍可移植；位于根目录真实路径下的路径也会被重定位。

当 Rspack 在其他位置恢复缓存时，会重定位根目录内的路径，也会根据相对位置重定位解析器在根目录上方记录的查找路径，例如 `../node_modules`。快照会在新位置校验这些路径。如果迁移后根目录的深度发生变化，曾查找到文件系统根目录的依赖会失效，因为新位置可能包含原解析器未搜索过的祖先目录。其他绝对路径保持原样，依赖这些路径的缓存条目会在根目录变化时重新构建。

:::tip
此前 `portable: true` 以 `context` 作为根目录。如需保留该根目录，请设置 `portable: { root: '.' }`，例如同一个包既在仓库内构建，又在不含 `.git` 的副本（如 Docker 构建上下文）中构建时。
:::

只有在项目布局相同时才会复用可移植缓存：`context` 在根目录中的位置相同，根目录与其真实路径的关系也相同。整体移动根目录（例如同一仓库的另一个 Git worktree）会保持布局不变。将包移动到仓库中的其他目录、添加或删除决定默认根目录的 `.git`，或者从其他位置的符号链接访问项目，都会开始一个新的缓存。布局不同的两个项目不应共用同一个缓存 [name](#name) 和 [storage](#storage) 位置。可移植缓存也不能在 Windows 与其他操作系统之间共享。

当 `portable` 为 `false` 时，缓存与项目的 [context](/config/context) 绑定。复制或共享到其他路径下的项目时，缓存会被视为失效，Rspack 会重新构建缓存。

[experiments.newCache](/config/experiments#experimentsnewcache) 启用的缓存后端尚不支持路径转换，因此即使 `portable` 为 `true`，它也始终与项目 context 绑定。

在旧版缓存后端中，仍依赖写入时项目根目录的缓存条目会在根目录变化时重新构建。这包括 `import.meta.url`、包含项目绝对路径的 loader 输出，以及对保持原样的路径的引用。在同一根目录下，未发生变化的构建仍可复用这些条目。

旧版缓存后端会重定位根目录内的入口上下文和模块标识，因此即使文件时间戳已更新，迁移后仍可复用未变化的模块。启用可移植缓存时，上下文依赖通过目录中各条目的名称、类型（文件、目录或符号链接）和内容进行校验。通过内容哈希回退校验的文件会刷新时间戳快照，供后续构建使用。

无法解析的符号链接通过其保存的目标路径进行跟踪。目录循环会被记录，但不会重复遍历同一目录。

如果 loader 将根目录内的绝对路径写入模块请求（例如来自 `require.resolve()` 的路径），该模块就会依赖根目录，因此 Rspack 会在迁移后重新构建它。将 `rebaseLoaderRequests` 设置为 `true` 后，这类请求会改写为相对于模块的路径，因此 loader 无需修改，模块也可以复用：

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
    portable: { rebaseLoaderRequests: true },
  },
};
```

这也适用于 Rspack 移除的分支中的请求，例如未启用 HMR 时的 `if (module.hot)`。读取请求的插件看到的是相对路径。模块也会变小，因此 [`optimization.splitChunks`](/plugins/split-chunks-plugin) 的分包结果可能与未启用此选项时不同。修改此选项会启用新的缓存。启用 [`experiments.portableCache`](/config/experiments#experimentsportablecache) 且未启用此选项时，如果构建中发现此选项可以改写的请求，Rspack 会通过 `rspack.persistentCache` 输出一条警告。

启用此选项后，Rspack 假定这类路径是针对当前检出目录计算的。如果应用了 `ExternalsPlugin`（包括 [`externals`](/config/externals)）或带有 `checkResource` 的 `IgnorePlugin`，则会禁用请求改写，因为它们可能依赖绝对路径写法。Rspack 会在每次编译中通过 `rspack.persistentCache` 输出一次禁用原因。如果 `IgnorePlugin` 的 `resourceRegExp` 只匹配某个请求两种写法中的一种，该请求也会保持原样。如果资源文件或 loader 添加为依赖的文件中包含根目录，或者设置了 [`resolve.roots`](/config/resolve#resolveroots)，或 [`resolve.alias`](/config/resolve#resolvealias)、[`resolve.fallback`](/config/resolve#resolvefallback) 中的绝对路径键，路径也会保持原样。如果 loader 通过其他方式获取路径（例如来自指向某个检出目录的环境变量），迁移后该路径会指向新的检出目录。这类 loader 应调用 `this.cacheable(false)`，或不启用此选项。

Rspack 还会将 `resolve` 选项中位于根目录内的绝对路径（例如 [`resolve.alias`](/config/resolve#resolvealias) 和 [`resolve.modules`](/config/resolve#resolvemodules)）视为随检出目录移动的路径。迁移后，如果某个检出目录的 `resolve` 选项指向另一个检出目录中的路径，Rspack 会重新解析请求，并保留模块构建结果。迁移后的构建会在读取缓存的检出目录重新运行模块工厂，包括工厂钩子和 `module.rules` 条件。工厂决策一致时，Rspack 保留缓存的构建结果；决策变化时则修复，包括匹配规则中的 loader 选项、按值比较的 parser 和 generator 选项，以及工厂钩子设置的请求。context 模块和 external 模块在其工厂结果一致时会被保留，这包括把 context 中的文件转换为其键的 resolver 选项（例如 [`resolve.extensions`](/config/resolve#resolveextensions)），但如果插件改变了 context 模块依赖的列出方式（例如带映射的 `ContextReplacementPlugin`），该模块会重新构建。其他不由普通模块工厂创建的模块（例如 Module Federation 的共享模块）会在迁移后重新构建。被多个导入方共享的模块由产生其缓存构建的导入方决定，这与全新构建一致：在全新构建中，最先到达该模块的导入方决定它的构建。符号链接通过其相对于根目录的目标进行校验，因此相对链接在迁移后仍然有效，而指向另一个检出目录的链接则会失效。这也包括迁移后才出现的链接，例如 `node_modules` 链接到主检出目录的 worktree。

Rspack 通过在缓存数据中查找根目录的原生写法、正斜杠写法、JSON 转义写法、JavaScript ASCII 转义写法、正则转义写法、base64 写法和 `file://` URL 写法，识别包含根目录的 loader 输出。这种查找只能尽力而为。如果 loader 根据路径生成输出，但输出中不包含上述任何写法（例如，对 `this.resourcePath` 进行哈希），应调用 `this.cacheable(false)` 或设置适当的 `cache.version`。如果 loader 或钩子读取描述文件中的数据（例如最近的 `package.json` 中的某个字段），必须通过 `this.addDependency()` 添加该文件：与原位置的热构建一样，否则 Rspack 不会比较其内容。如果模块的 loader 调用了 `this.importModule`，该模块会在迁移后重新构建。匹配规则中的 loader 选项，包括 pre、normal 和 post 规则中数组和函数形式的 `use`，会按值进行比较，包括 `Set`、`Map`、`Date` 和 `RegExp`。根目录内的绝对路径被视为随检出目录移动；根据检出位置派生的其他值（例如目录名）发生变化时，会使模块在迁移后重新构建。数组形式 `use` 的选项中的函数和插件实例被假定与检出目录无关：任意两个函数比较结果相等，实例则按类名及其自身数据比较。如果插件将检出路径写入输出，但输出中不包含该路径的任何写法，则需要设置适当的 `cache.version`。在函数形式 `use` 的返回结果中，函数、symbol 或类实例会使模块在迁移后重新构建，并且不会缓存其 loader 结果。任何 loader 选项中的循环引用也是如此。在任何 loader 选项中，getter、proxy、不可枚举或以 symbol 为键的属性、`Date`、`RegExp`、`Set` 或 `Map` 的自身属性，以及其他内置类的实例（例如 `URL` 或 `ArrayBuffer`）同样会使模块在迁移后重新构建，因为 Rspack 无法在不运行代码或不遗漏状态的情况下读取它们。`RegExp` 还会比较其 `lastIndex`，冻结、密封和只读的选项也会按该状态比较。

base64 检测也涵盖较短的项目根目录。如果根目录太短，无法在所有 base64 字节对齐位置检测到（例如 `/`），Rspack 会保守地将所有编码后的缓存条目与该根目录绑定，根目录变化时这些条目会重新构建。

**示例：**

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
    portable: { root: '../..' },
  },
};
```

### readonly

- **类型：** `boolean`
- **默认值：** `false`

启用只读缓存模式。启用后，缓存将仅从磁盘读取而不会被写入，这在 CI 环境中非常有用，可以使用预热的缓存而不修改它。

**示例：**

仅在 CI 启用：

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
    // 请确保你的 CI 环境设置了 `process.env.CI`（或类似的环境变量）
    readonly: Boolean(process.env.CI),
  },
};
```

### snapshot

- **类型：** `object`
- **默认值：** `{ immutablePaths: [], managedPaths: [/[\\/]node_modules[\\/][^.]/], unmanagedPaths: [] }`

配置持久化缓存的快照策略，用于判断自上次构建以来哪些依赖发生了变化。

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
    snapshot: {
      managedPaths: [/[\\/]node_modules[\\/]/],
    },
  },
};
```

#### snapshot.immutablePaths

- **类型：** `(RegExp | string)[]`
- **默认值：** `[]`

不可变路径数组。从持久化缓存恢复时，Rspack 会将匹配的路径视为未变化，并且不会重新检查其内容。适用于写入后保证不再变化的内容寻址路径。

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
    snapshot: {
      immutablePaths: [/[\\/]\.yarn[\\/]cache[\\/]/],
    },
  },
};
```

#### snapshot.managedPaths

- **类型：** `(RegExp | string)[]`
- **默认值：** `[/[\\/]node_modules[\\/][^.]/]`

包管理器管理的路径数组。从持久化缓存恢复时，Rspack 会通过对应 `package.json` 中的 `version` 字段判断包是否发生变化，而不是对文件内容进行哈希。这可以加速对仅通过包管理器更新的依赖包的缓存校验。

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
    snapshot: {
      managedPaths: [/[\\/]node_modules[\\/]/],
    },
  },
};
```

#### snapshot.unmanagedPaths

- **类型：** `(RegExp | string)[]`
- **默认值：** `[]`

指定 [`cache.snapshot.managedPaths`](#snapshotmanagedpaths) 中不应被视为包管理器管理的路径。这些路径下的文件会回退到基于内容哈希的缓存校验。

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
    snapshot: {
      unmanagedPaths: [/[\\/]node_modules[\\/]my-linked-package[\\/]/],
    },
  },
};
```

### storage

- **类型：** `{ type: 'filesystem'; directory?: string; location?: string }`

配置缓存存储。目前仅支持文件系统存储。

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
    storage: {
      type: 'filesystem',
    },
  },
};
```

#### storage.type

- **类型：** `'filesystem'`
- **默认值：** `'filesystem'`

通过 `type` 设置缓存存储类型。目前仅支持文件系统存储。

#### storage.directory

- **类型：** `string`
- **默认值：** `node_modules/.cache/rspack`

`cache.storage.directory` 是持久化缓存的基础目录，语义与 webpack 的 `cache.cacheDirectory` 一致。相对路径会基于 [`config.context`](/config/context) 解析。

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
    storage: {
      type: 'filesystem',
      directory: '.rspack-cache',
    },
  },
};
```

#### storage.location

<ApiMeta addedVersion="2.1.8" />

- **类型：** `string`
- **默认值：** `<storage.directory>/<cache.name>`

`cache.storage.location` 是 Rspack 实际读写缓存数据的完整路径，语义与 webpack 的 `cache.cacheLocation` 一致。未设置时，Rspack 会根据 `cache.storage.directory` 和 `cache.name` 推导该路径。相对路径会基于 [`config.context`](/config/context) 解析。

```js title="rspack.config.mjs"
export default {
  context: '/project',
  cache: {
    type: 'persistent',
    name: 'client',
    storage: {
      type: 'filesystem',
      directory: '.rspack-cache',
    },
  },
};

// cache.storage.location 的默认值为 '/project/.rspack-cache/client'。
```

如需覆盖推导出的路径，可以显式设置 `storage.location`：

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
    storage: {
      type: 'filesystem',
      location: '.custom-cache/client',
    },
  },
};
```

### 查看持久化缓存日志

持久化缓存相关日志会通过 `rspack.persistentCache` logger 输出。可以通过 `stats.loggingDebug` 开启这个 logger，在构建 stats 中查看这些日志：

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
  },
  stats: {
    logging: false,
    loggingDebug: /^rspack\.persistentCache$/,
  },
};
```

日志会包含持久化缓存的关键信息，例如持久化缓存是否启用、构建依赖是否有效、缓存恢复是否成功，以及持久化缓存失效的原因。日志还会包含各缓存阶段的读写耗时（例如构建依赖校验、快照恢复、`occasion` 恢复、暂存以及刷盘）。

如果也想同时打印其他 logger 的日志，可以开启 `stats.logging`：

```js title="rspack.config.mjs"
export default {
  cache: {
    type: 'persistent',
  },
  stats: {
    logging: 'info',
    loggingDebug: /^rspack\.persistentCache$/,
  },
};
```

## 禁用缓存

将 `cache` 设置为 `false` 可以同时禁用内存缓存和持久化缓存，但不会关闭 [`incremental`](/config/incremental)。如果工作流要求完整重建且不恢复 Artifact，需要另外设置 `incremental: false`。

通常不建议禁用缓存，因为未被 Incremental 跳过的计算将无法再复用细粒度 Cache entry。

```js title="rspack.config.mjs"
export default {
  cache: false,
};
```
