# ESM 产物

Rspack 可以将应用和库打包为 ES 模块（ESM）。[构建浏览器应用](#build-a-browser-application)时，页面可以通过 `<script type="module">` 加载应用入口。[构建 ESM 库](#build-an-esm-library)时，其他项目可以通过包名导入库提供的函数或组件。

## 构建浏览器应用 \{#build-a-browser-application}

默认情况下，Rspack 会将浏览器应用打包为普通脚本，通常用立即执行函数（IIFE）包裹代码。要生成 CommonJS 或 ESM 产物，需要在 `output` 中指定相应的格式。

如果你的应用面向支持 ES 模块和动态 `import()` 的浏览器，可以启用 [`output.module`](/config/output#outputmodule)。配合 [`HtmlRspackPlugin`](/plugins/html-rspack-plugin) 使用时，插件会在生成的 HTML 中引用实际的入口文件，并为脚本添加 `type="module"`。

```js title="rspack.config.mjs"
import { rspack } from '@rspack/core';

export default {
  target: ['web', 'es2020'],
  output: {
    module: true,
  },
  plugins: [new rspack.HtmlRspackPlugin()],
};
```

使用这份配置时，Rspack 会将异步 chunk 打包为 ES 模块。浏览器在需要时通过原生 `import()` 加载这些模块。

你可以在 [React 热更新示例](https://github.com/rstackjs/rstack-examples/tree/main/rspack/react-refresh-esm) 和 [React 服务端渲染示例](https://github.com/rstackjs/rstack-examples/tree/main/rspack/react-ssr-esm) 中查看完整配置。

## 构建 ESM 库 \{#build-an-esm-library}

开发 JavaScript 库或 UI 组件库时，推荐使用 [Rslib](https://rslib.rs/zh/guide/start/quick-start)。它基于 Rsbuild，为库的构建、调试和测试提供开箱即用的支持。相比直接配置 Rspack，用 Rslib 可以更方便地生成多种格式的产物和 TypeScript 类型声明。

如果你需要直接使用 Rspack 构建 ESM 库，可以将 [`output.library.type`](/config/output#outputlibrarytype) 设为 `'modern-module'`。构建后的文件会保留入口的 ESM 导出，便于下游打包器通过 [tree shaking](/guide/optimization/tree-shaking) 移除未使用的代码。

例如，要让使用者能通过 `import { formatDate } from 'my-lib'` 导入日期格式化函数，先在 `my-lib` 的入口文件中导出这个函数。

```js title="src/index.js"
export function formatDate(date) {
  return date.toISOString().slice(0, 10);
}
```

将入口命名为 `index`，并将 `output.filename` 设为 `'[name].js'`。Rspack 会以 ESM 格式生成 `dist/index.js`。

```js title="rspack.config.js"
export default {
  entry: { index: './src/index.js' },
  output: {
    filename: '[name].js',
    library: { type: 'modern-module' },
  },
};
```

在 `package.json` 中设置 `"type": "module"`，让 Node.js 将包内的 `.js` 文件作为 ES 模块加载。再将 `exports` 指向构建产物，这样使用者就可以从 `my-lib` 导入 `formatDate`。

```json title="package.json"
{
  "name": "my-lib",
  "type": "module",
  "exports": "./dist/index.js"
}
```

如果组件库的每个组件都有独立的源文件，希望在构建产物中保留这样的目录结构，可以配置 [`output.library.preserveModules`](/config/output#outputlibrarypreservemodules)。你也可以参考[使用 Rspack 构建 ESM 库的完整示例](https://github.com/rstackjs/rstack-examples/tree/main/rspack/library-esm)。

## 可选配置 \{#optional-configuration}

- ESM 入口文件默认使用 `.mjs` 扩展名。如果需要调整文件名，可以通过 [`output.filename`](/config/output#outputfilename) 配置入口文件名，通过 [`output.chunkFilename`](/config/output#outputchunkfilename) 配置异步 chunk 的文件名。
- 为了避免同一 chunk 中的变量名冲突，Rspack 有时会用 IIFE 包裹入口模块。启用 [`optimization.avoidEntryIife`](/config/optimization#optimizationavoidentryiife) 后，Rspack 会尝试通过重命名变量省去这层包装。
- 如果应用需要在 Web Worker 中加载异步 chunk，可以通过 [`output.workerChunkLoading`](/config/output#outputworkerchunkloading) 单独配置 Worker 内的加载方式。
- 部署时，请确保服务器以 JavaScript MIME 类型（如 `text/javascript`）返回模块文件。如果页面从 CDN 跨域加载脚本，还需要在 CDN 上配置 CORS 响应头，允许页面所在的源访问这些文件。
- 构建 React 组件库时，如果希望复用应用已安装的 React，可以通过 [`externals`](/config/externals#externals) 将 `react` 排除在打包范围之外。生成的代码如何引用它，由 [`externalsType`](/config/externals#externalstype) 决定。
- 如果希望保留未压缩的库代码，方便阅读或调试，可以将 [`optimization.minimize`](/config/optimization#optimizationminimize) 设为 `false`。
