# Loader

Rspack 内置了对 JavaScript、CSS、JSON、静态资源等模块类型的支持。

Loader 是一种模块转换器，它将各种类型的模块转换为 Rspack 支持的类型。通过使用不同类型的 loader，你可以扩展 Rspack 来处理额外的模块类型，例如 JSX、Markdown、Sass、Less 等。

当 Rspack 打包一个模块时，先通过 loader 对模块进行预处理，将它们转换为 Rspack 支持的模块类型，然后再根据 [rules[].type](/config/module-rules#rulestype) 对模块进行后置处理。

## webpack loader 兼容

Rspack 允许你使用社区中绝大多数的 webpack loaders。查看 [社区 loader](/guide/start/ecosystem#loaders) 发现社区提供的 loaders。

如果你发现有 Rspack 不支持的 loader，欢迎通过 [GitHub Issues](https://github.com/web-infra-dev/rspack/issues) 与我们交流。

## 编写 Loader

参考 [编写 Loader](/api/loader-api/writing-loaders) 了解如何开发一个 Loader。

## 示例

### 使用 Less

你可以使用 [less-loader](https://github.com/webpack/less-loader) 对 `.less` 文件的内容做相应的转换：

```js title="rspack.config.mjs"
export default {
  module: {
    rules: [
      {
        test: /\.less$/,
        use: [
          {
            loader: 'less-loader',
          },
        ],
        type: 'css',
      },
    ],
  },
};
```

[less-loader](https://github.com/webpack/less-loader) 可以将 Less 文件转换为 Rspack 支持的 CSS 模块类型，因此你可以设置 type 为 `'css'` 以指示 Rspack 使用原生支持的 CSS 策略进行后处理。

### 使用多个 Loader

你可以对特定的 [Rule](/config/module-rules#rule) 匹配项使用多个 loader 进行链式处理，loader 的执行顺序为**从右往左**。

例如，你可以使用 [less-loader](https://github.com/webpack/less-loader) 完成 Less 到 CSS 类型之间的转换，并对转换后的源码使用 [postcss-loader](https://github.com/webpack/postcss-loader) 进行二次转换，并最终交给 Rspack 的 CSS 后处理器，完成进一步处理：

```js title="rspack.config.mjs"
export default {
  module: {
    rules: [
      {
        test: /\.less$/,
        use: [
          {
            loader: 'postcss-loader',
          },
          {
            loader: 'less-loader',
          },
        ],
        type: 'css',
      },
    ],
  },
};
```

### 传递配置项

你可以使用 [rules[].use](/config/module-rules#rulesuse) 给 loader 传递相关配置，例如：

```js title="rspack.config.mjs"
export default {
  module: {
    rules: [
      {
        test: /\.css$/,
        use: [
          {
            loader: 'postcss-loader',
            options: {
              postcssOptions: {
                // ...
              },
            },
          },
        ],
        type: 'css',
      },
    ],
  },
};
```

### 使用自定义 Loader

你可以在 Rspack 中使用自定义 loader，下面我们会编写一个简单的 banner-loader 作为示例。

banner-loader 的作用是在每个模块的头部添加一个 banner 注释，例如添加一段 License 信息：

```js
/**
 * MIT Licensed
 * Copyright (c) 2022-present ByteDance, Inc. and its affiliates.
 * https://github.com/web-infra-dev/rspack/blob/main/LICENSE
 */
```

在项目的根目录新建一个 `banner-loader.js` 的文件，内容如下：

```js title="banner-loader.js"
const BANNER = `/**
 * MIT Licensed
 * Copyright (c) 2022-present ByteDance, Inc. and its affiliates.
 * https://github.com/web-infra-dev/rspack/blob/main/LICENSE
 */`;

module.exports = function (content) {
  return `${BANNER}\n${content}`;
};
```

Loader 的第一个入参为文件的内容，我们可以在这里对文件内容进行处理，然后返回处理后的内容。编写完后，我们需要将这个 loader 使用 CommonJS 风格进行导出。

上述示例中，我们会在所有匹配的文件的头部添加一个 banner 注释，如果我们希望将这个行为匹配所有以 `js` 结尾的文件，我们可以这样配置：

```js title="rspack.config.mjs"
export default {
  module: {
    rules: [
      {
        test: /\.js$/,
        loader: './banner-loader.js',
      },
    ],
  },
};
```

更多关于 Loader API 的信息，请参考 [loader-api](/api/loader-api/)

## 并行 Loader \{#parallel-loader}

Rspack 支持将 loader 放入 worker threads 中并行执行，可以更好地利用多核 CPU，提升构建性能。

要为 loader 启用并行执行，请在 [rules[].use](/config/module-rules#rulesuse) 中设置 `parallel` 选项：

```js title="rspack.config.mjs"
export default {
  module: {
    rules: [
      {
        test: /\.less$/,
        use: [
          {
            loader: 'less-loader',
            parallel: true,
            options: {},
          },
        ],
        type: 'css',
      },
    ],
  },
};
```

设置 `parallel: true` 会启用并行执行，并由 Rspack 自动选择合适的线程数量。

当同一条 Rule 下多个 loader 都开启了 `parallel` 选项，Rspack 会在同一个 worker 中按顺序依次运行这些 loader，直到遇到未启用 parallel 的 loader 或 Rust 实现的 builtin loader。这样可以在保证 loader 顺序的前提下最大化并行效率。

:::tip

- loader 选项必须是对象。选项可以包含函数，函数在主线程执行。
- native binding 使用 worker 执行并行 loader。由于独立的 WebAssembly 实例无法共享 native task 队列，WASI binding 保留在主线程执行 loader 的兼容行为。
- compiler 和 compilation API 通过代理访问主线程实现。worker 执行 loader 时跳过 `NormalModule.getCompilationHooks(compilation).loader`，pitch 阶段也会跳过。并行 loader 无法使用该 hook 添加的属性和方法。非并行 loader 段仍在主线程执行该 hook。
- 可序列化的 loader options 和 `additionalData` 使用 V8 序列化，字节保存在 Rust 中，由消费数据的线程反序列化。数据图内部的循环引用和共享引用会保留，但不保留原对象跨线程的身份。含函数的 options 和不可序列化值仍使用对象桥。
- `_module` 提供由 worker 本地 native module 支持的受限 API，包括 resource 和 request 属性、`identifier()`、`readableIdentifier()`、`nameForCondition()`、`originalSource()`、`size()`、`libIdent()`、`factoryMeta`、`matchResource` 和 `emitFile()`。不提供 `blocks`、`dependencies`、`error` 等依赖 compilation 的 API。仅在 loader 执行期间使用此对象。
- `buildInfo`（包括自定义字段和 assets 查询）继续通过主线程对象桥访问。worker emit 的文件直接保存在 native module 中，供 compilation 后续使用。

:::

更多细节请参考 [rules[].use.parallel](/config/module-rules#rulesuseparallel)。

### 严格模式 \{#strict-execution}

使用 native binding 时，`parallel: 'strict'` 与普通 parallel loader 共用 worker 池和 MPMC 队列，但跳过主线程 API 桥接的准备。适用于仅转换输入的 loader，例如设置 `cacheDirectory: false` 的 `babel-loader`。

- loader options 和顶层 `loader` 设置必须可序列化。
- `_compiler`、`_compilation`、`fs`、`importModule` 和 compilation diagnostics 不可用。`getLogger()` 丢弃日志。
- `getResolve(options)` 和 `resolve` 直接调用 Rust resolver，并记录依赖。
- 可以通过 `this._module` 访问当前模块数据。自定义 `buildInfo` 字段仅在当前 strict 执行段内可见。
- 可以通过 `emitFile` 写入 asset，但不能通过 `buildInfo.assets` 读取。
- 收到的 `additionalData` 为 `undefined`，通过 loader 回调返回的值会被忽略。

普通 parallel loader 保留通过 message port 代理访问主线程 API 的行为。两种模式均跳过 loader hook，非 parallel loader 保留该 hook。
