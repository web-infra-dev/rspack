# 资源基础路径

Rspack 提供了 [output.publicPath](/config/output#outputpublicpath) 选项，用于设置打包后的静态资源文件（如 JS、CSS、图片等）的 URL 路径前缀，它决定了你的应用在浏览器中如何加载这些资源。

## 使用场景

想象一下以下场景:

- 你的静态资源需要部署到 CDN
- 你的 web 应用并不是部署在域名根路径下
- 你需要根据不同环境（开发、测试或生产）来使用不同的资源路径

在这些场景下，配置 `output.publicPath` 可以帮助你正确地加载静态资源。

## 基础示例

将 `output.publicPath` 设置为 `/`，则资源路径会相对于根路径。

```js title="rspack.config.mjs"
export default {
  output: {
    publicPath: '/',
  },
};
```

在这种配置下，资源访问路径为 `http://[domain]/`，例如 `http://localhost:8080/main.js`。

## 子目录

如果你的应用需要部署在某个子目录下，可以将 `output.publicPath` 设置为对应的子目录路径：

```js title="rspack.config.mjs"
export default {
  output: {
    publicPath: '/assets/',
  },
};
```

在这种配置下，所有资源都会从 `/assets/` 路径下加载，例如 `http://localhost:8080/assets/main.js`。

:::tip

- `output.publicPath` 的值通常以 `/` 结尾。
- 当 `output.publicPath` 为 `./assets/` 或空字符串这样的相对路径时，资源 URL 取决于解析时使用的基准地址。在浏览器中，这个地址通常来自页面 URL，因此嵌套的页面路径或 HTML `<base>` 元素都可能影响资源的加载位置。关于 Rspack 如何解析资源 URL，参阅 [Base URI](#base-uri)。

:::

## 使用 CDN

在使用 CDN 来部署静态资源时，你可以根据环境变量来设置 `output.publicPath`，在生产构建时设置为 CDN 的 URL 前缀。

```js title="rspack.config.mjs"
const isProd = process.env.NODE_ENV === 'production';

export default {
  output: {
    publicPath: isProd ? 'https://cdn.example.com/' : '/',
  },
};
```

在这种配置下：

- 在开发模式下，资源访问路径为 `http://[domain]/`，例如 `http://localhost:8080/main.js`。
- 在生产模式下，资源访问路径为 `https://cdn.example.com/`，例如 `https://cdn.example.com/main.[hash].js`。

## 动态设置 publicPath

在 JavaScript 代码中，你可以通过 Rspack 的 [`import.meta.rspackPublicPath`](/api/runtime-api/module-variables#importmetarspackpublicpath) 来动态设置 `publicPath`。

`import.meta.rspackPublicPath` 会覆盖 Rspack 配置中的 `output.publicPath`，但它只能对异步加载的资源生效，不会对 HTML 中通过 `<script src="...">` 加载的资源生效。

首先创建一个 `publicPath.js`：

```js title="publicPath.js"
import.meta.rspackPublicPath =
  location.hostname === 'foo.com'
    ? 'https://cdn1.com/assets/'
    : 'https://cdn2.com/assets/';
```

然后在入口文件的第一行引入它，以确保 `publicPath` 在异步资源被加载之前被设置：

```js title="entry.js"
import './publicPath.js';
import './others.js';
```

## 自动 publicPath

在某些情况下，你可能事先并不知道 `publicPath` 应该设置为什么值。这时 Rspack 可以通过解析一些变量来自动计算出 `publicPath` 的值，这些变量包括 [import.meta.url](/api/runtime-api/module-variables#importmetaurl)、[document.currentScript](https://developer.mozilla.org/en-US/docs/Web/API/Document/currentScript)、`script.src` 或 `self.location`。

你只需要将 `output.publicPath` 设置为 `'auto'` 即可：

```js title="rspack.config.mjs"
export default {
  output: {
    // 当 `target` 为 `'web'` 或 `'webworker'` 时，这是默认值
    publicPath: 'auto',
  },
};
```

如果应用运行时报出 `Automatic publicPath is not supported in this browser` 错误，请参阅[无法自动确定 publicPath](/guide/diagnostics/runtime-issues#automatic-publicpath-cannot-be-determined)。

## Base URI

`publicPath` 决定生成的资源 URL 前缀。当资源 URL 是相对地址时，还需要一个**基准 URI（Base URI）**才能将它解析为完整 URL。例如，基准 URI 为 `https://example.com/app/index.html` 时：

| 生成的资源 URL                     | 解析后的 URL                               |
| ---------------------------------- | ------------------------------------------ |
| `assets/logo.png`                  | `https://example.com/app/assets/logo.png`  |
| `/assets/logo.png`                 | `https://example.com/assets/logo.png`      |
| `https://cdn.example.com/logo.png` | `https://cdn.example.com/logo.png`（不变） |

相对路径会基于基准 URI 所在的目录解析；以 `/` 开头的路径会使用其协议和域名。绝对 URL 则不依赖基准 URI。

默认情况下，Rspack 会使用这个基准 URI 解析 `new URL('./logo.png', import.meta.url)` 对应的产出资源 URL，以及 `new Worker(new URL('./worker.js', import.meta.url))` 对应的 Worker URL。这并不意味着所有资源加载方式都会使用 Rspack 的基准 URI，例如 HTML 中的 `<script>` 和 `<link>` 元素，其 URL 由浏览器解析。

### 默认基准 URI \{#default-base-uri}

通常无需配置基准 URI，它的默认值取决于运行环境和 chunk 加载方式：

- 浏览器构建使用默认 chunk 加载方式时，值为 `document.baseURI || self.location.href`，取决于页面 URL 和 HTML `<base>` 元素。
- Node.js 构建使用常规 CommonJS 输出时，值为根据产物位置生成的 `file:` URL。

浏览器构建默认使用 `publicPath: 'auto'`，通常会根据 bundle 地址生成绝对资源 URL，基准 URI 不会影响这些 URL。Node.js 构建默认使用 `publicPath: ''`，相对资源路径则会基于上述 `file:` URL 解析。

你可以通过 [`import.meta.rspackBaseUri`](/api/runtime-api/module-variables#importmetarspackbaseuri) 读取当前值：

```js
const baseUri = import.meta.rspackBaseUri;
console.log(baseUri);
```

也可以将这个值作为 `new URL()` 的第二个参数，解析运行时提供的路径。这只是 URL 解析操作，不会让 Rspack 打包所引用的文件。需要打包资源时，请使用 `new URL('./logo.png', import.meta.url)`。

### 修改基准 URI \{#overriding-the-base-uri}

如果只需要调整资源的部署地址，通常配置 `publicPath` 即可。当相对资源 URL 需要基于其他地址解析时，可以修改基准 URI：

- 如果地址在构建时就已确定，通过 [`entry.baseUri`](/config/entry#entrydescriptionbaseuri) 设置入口的初始基准 URI。
- 如果地址在运行时才能确定，在创建资源 URL 前为 [`import.meta.rspackBaseUri`](/api/runtime-api/module-variables#importmetarspackbaseuri) 赋值。

例如，下面的配置使用 `publicPath: ''` 保留图片资源的相对路径，让基准 URI 决定其完整地址：

```js title="rspack.config.mjs"
export default {
  output: {
    publicPath: '',
    assetModuleFilename: 'assets/[name][ext]',
  },
  module: {
    rules: [{ test: /\.png$/, type: 'asset/resource' }],
  },
};
```

然后在应用中设置部署目录，再创建图片 URL：

```js title="src/index.js"
// 目录地址应以 / 结尾。
import.meta.rspackBaseUri = 'https://example.com/app/';

const logoUrl = new URL('./logo.png', import.meta.url);
console.log(logoUrl.href); // https://example.com/app/assets/logo.png
```

这会修改 Rspack 运行时使用的基准 URI，不会修改 HTML 的 `<base>` 元素、HTML 中的资源地址或已有的 `URL` 对象。如果导入的模块会在初始化时创建资源 URL，请将基准 URI 的设置放在单独的初始化模块中，并确保它先于这些模块执行。
