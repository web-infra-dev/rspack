# Introduction

Rspack is a high-performance web bundler written in Rust. It offers a modernized webpack API, enabling a seamless transition from webpack while delivering lightning-fast build speeds.

## Why Rspack?

### Faster development feedback

Rspack was originally designed to address build performance challenges in large JavaScript applications. Written in Rust, it uses a parallel architecture to take full advantage of multi-core CPUs, along with [incremental compilation](/config/incremental), [lazy compilation](/guide/advanced/lazy-compilation), and [persistent caching](/config/cache) to make builds more efficient.

These improvements significantly reduce dev server startup, hot module replacement (HMR), and production build times, making Rspack more than 10 times faster than webpack.

### Make your code run faster

Rspack aims to produce smaller bundles that run faster. Optimizations such as [tree shaking](/guide/optimization/tree-shaking) and minification help eliminate redundant code and reduce asset sizes.

Rspack also provides powerful [code splitting](/guide/optimization/code-splitting) capabilities, giving you fine-grained control over how modules are split and shared to achieve optimal loading performance for JavaScript applications.

### From ready to use to fully customizable

The Rspack ecosystem includes tools for a range of use cases, such as [Rsbuild](https://rsbuild.rs) for application development, [Rslib](https://rslib.rs) for library development, and [Rspress](https://rspress.rs) for documentation sites. These tools work out of the box, reducing the effort needed to set up and maintain your toolchain.

When you need deeper customization, you can use Rspack's configuration options, plugins, and JavaScript API to tailor the build process or develop your own tools. For advanced use cases such as micro-frontends and server-side rendering, Rspack also supports [Module Federation](/guide/advanced/module-federation), [MultiCompiler mode](/api/javascript-api/#multicompiler), and [React Server Components](/guide/integrations/rsc).

### Compatible with the webpack ecosystem

Rspack is compatible with the vast majority of webpack's configuration options and APIs, allowing you to reuse existing loaders and plugins. Teams already using webpack can continue to apply their configuration expertise and use their custom plugins.

See the [webpack migration guide](/guide/migration/webpack) and [plugin compatibility list](/plugins/community-plugin-compatibility) to learn more.

## Meet Rstack

We built **Rstack** around Rspack: a high-performance JavaScript toolchain for developers and AI agents. It supports application development, library development, and documentation sites out of the box, while integrating testing, linting, and build analysis into the development workflow to reduce the effort of configuring and connecting tools.

| Tool                             | Purpose                                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------- |
| [Rsbuild](https://rsbuild.rs/)   | Build tool with default configuration, a dev server, and framework integrations       |
| [Rslib](https://rslib.rs/)       | Library development tool for building JavaScript libraries and UI component libraries |
| [Rspress](https://rspress.rs/)   | Static site generator for documentation sites and other content-driven websites       |
| [Rstest](https://rstest.rs/)     | Testing framework for unit and end-to-end testing                                     |
| [Rslint](https://rslint.rs/)     | Linter with type-aware rules                                                          |
| [Rsdoctor](https://rsdoctor.rs/) | Build analysis tool for analyzing build times and bundle sizes                        |
| [Rstack CLI](https://rstack.rs/) | Unified CLI with the full suite of Rstack tools built in                              |

These tools can be used independently or together. Start with the tools that fit your current needs and adopt others as your project grows.
