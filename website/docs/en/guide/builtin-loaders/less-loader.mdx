# Less loader

`builtin:less-loader` uses `less-rs` to compile Less to CSS. It is included in Rspack and does not require installing `less` or `less-loader`.

Use it with Rspack's CSS support:

```js title="rspack.config.mjs"
export default {
  module: {
    rules: [
      {
        test: /\.less$/,
        type: 'css/auto',
        use: [
          {
            loader: 'builtin:less-loader',
            /** @type {import('@rspack/core').LessLoaderOptions} */
            options: {
              lessOptions: {
                math: 'parens-division',
              },
            },
          },
        ],
      },
    ],
  },
};
```

For example, this input produces `.box { width: 12px; }`:

```less title="style.less"
@size: 6px;
.box {
  width: @size * 2;
}
```

Import `style.less` from your application entry. You can also place `css-loader` and `style-loader` before `builtin:less-loader` in `use`, with the module type set to `javascript/auto`.

The loader accepts the following options. The `LessLoaderOptions` and `LessOptions` types are exported by `@rspack/core`.

| Option            | Description                                                                                                                                                      |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sourceMap`       | Generate source maps. Defaults to Rspack's loader source map setting derived from `devtool`. Maps are passed to the next loader and composed with incoming maps. |
| `additionalData`  | A string of Less code prepended to each resource, followed by a newline.                                                                                         |
| `webpackImporter` | Use Rspack's resolver after Less lookup (`true`, default), disable it (`false`), or skip Less lookup (`"only"`).                                                 |
| `lessOptions`     | Less compiler options listed below.                                                                                                                              |

`lessOptions` is passed to the Less.js-compatible options parser in `less-rs`. Compiler options include:

- Output and evaluation: `compress`, `strictUnits`, `math`, `strictMath`, `dumpLineNumbers`, `banner`, `globalVars`, and `modifyVars`.
- Imports and URLs: `filename`, `paths`, `processImports`, `strictImports`, `rewriteUrls`, `relativeUrls`, `rootpath`, and `urlArgs`.
- Diagnostics and source maps: `quiet`, `quietDeprecations`, and `sourceMap` (a boolean or a Less source map options object).

The loader defaults to `relativeUrls: true` and `filename: resourcePath`, matching JavaScript `less-loader`. `relativeUrls: true` takes precedence over `rewriteUrls`; set `relativeUrls: false` to use `rewriteUrls: 'off'` or `'local'`. Similarly, `strictMath: true` overrides `math` with `'parens'`. Numeric `math` and `rewriteUrls` values are also accepted.

Variable values can be strings or numbers. `paths` accepts a string or an array of strings; relative entries resolve from Rspack's `context`.

When the loader's source map setting is enabled, it replaces `lessOptions.sourceMap` with settings that embed source contents, preserve absolute source paths, and omit the source map URL comment. Otherwise, an explicit `lessOptions.sourceMap` is preserved, matching JavaScript `less-loader`.

Compiler options are interpreted by `less-rs`, including its handling of unknown fields. Unknown loader-level options are rejected.

By default, imports first use Less's native lookup (including `lessOptions.paths`), then fall back to Rspack's resolver. This supports `resolve.alias`, package `exports`, and legacy `~` package imports. Prefer imports without `~` in new code. The resolver inherits the project's resolve configuration, adds `less` and `style` conditions and the `less`, `style`, and `main` entry fields, and tries `.less` and `.css` extensions. `resolve.byDependency.less` can customize Less resolution.

Set `webpackImporter: false` to use only Less lookup, or `webpackImporter: "only"` to resolve imports exclusively through Rspack. In the default mode, a file found by Less takes precedence over an alias for the same request. `~package` requests go directly to the Rspack resolver.

Node-style package lookup resolves symlinks before evaluating nested imports, so pnpm packages can find dependencies from their real locations. This uses Rspack's input file system.

Resolved files are still parsed and evaluated together by less-rs, preserving cross-import variables and mixins. Reads use Rspack's input file system. Imported files, resolver dependencies (including package manifests), and files read by functions such as `data-uri()` are tracked as file dependencies. Missing imports, including optional imports, are tracked for watch mode. CSS imports left in the output are handled by the following CSS pipeline.

This loader supports a subset of the JavaScript `less-loader` options. It does not support function-valued options, custom JavaScript implementations or plugins, JavaScript evaluation, or HTTP imports. Use the JavaScript `less-loader` when those features are required. JavaScript expression evaluation and JavaScript plugins are separate capabilities; enabling expression evaluation alone does not provide the Less plugin API.

Passing compiler flags such as `javascriptEnabled`, `insecure`, or `disablePluginRule` does not add JavaScript or HTTP support to `less-rs` or the loader.
