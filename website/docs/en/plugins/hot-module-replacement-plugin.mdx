# HotModuleReplacementPlugin

Enables hot module replacement (HMR).

## Examples

Enabling HMR is straightforward and in most cases no options are necessary.

Note that HMR can not be used in production build. You can use `process.env.NODE_ENV` to determine if it is a development environment.

```js title="rspack.config.mjs"
import { rspack } from '@rspack/core';
const isDev = process.env.NODE_ENV === 'development';

export default {
  plugins: [isDev && new rspack.HotModuleReplacementPlugin()],
};
```

## Runtime API

When you register the `HotModuleReplacementPlugin` plugin, Rspack will inject HMR related runtime APIs, such as `module.hot` and `import.meta.webpackHot`.

See [HMR API](/api/runtime-api/hmr) for more details.

## Hot update manifest

During HMR, the runtime reads a `hot-update.json` manifest to find out which chunks need updates and which chunks or modules need removal. The manifest contains IDs, while the updated JavaScript code is in separate `hot-update.js` files.

For example, this manifest tells the runtime to update the JavaScript and built-in CSS for the `main` chunk, with no chunks or modules to remove:

```json
{
  "c": ["main"],
  "r": [],
  "m": [],
  "css": { "c": ["main"] }
}
```

| Field       | Meaning and purpose                                                                                  |
| ----------- | ---------------------------------------------------------------------------------------------------- |
| `c`         | Chunk IDs with JavaScript updates. The runtime uses these IDs to load the needed update files.       |
| `r`         | Chunk IDs to remove from the current runtime.                                                        |
| `m`         | Module IDs to remove from the current runtime.                                                       |
| `css.c`     | Chunk IDs whose built-in CSS needs updating. The runtime reloads their stylesheets.                  |
| `css.r`     | Chunk IDs whose built-in CSS has been removed. The runtime removes their old stylesheets.            |
| `miniCss.c` | Like `css.c`, but for CSS extracted by [CssExtractRspackPlugin](/plugins/css-extract-rspack-plugin). |
| `miniCss.r` | Like `css.r`, but for CSS extracted by `CssExtractRspackPlugin`.                                     |

`css` and `miniCss` are optional objects, and their `c` and `r` fields are omitted when empty. CSS updates are tracked separately from JavaScript updates to avoid reloading unchanged stylesheets. Removing a chunk's CSS does not necessarily remove the chunk itself.

The manifest filename is controlled by [output.hotUpdateMainFilename](/config/output#outputhotupdatemainfilename). With `output.module: true`, the manifest is exported as an ES module instead of plain JSON.
