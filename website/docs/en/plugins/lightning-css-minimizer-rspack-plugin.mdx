# LightningCssMinimizerRspackPlugin

<ApiMeta specific={['Rspack']} />

This plugin uses [lightningcss](https://lightningcss.dev/) to minify CSS assets. See [optimization.minimizer](/config/optimization#optimizationminimizer).

## Examples

```js title="rspack.config.mjs"
import { rspack } from '@rspack/core';

export default {
  mode: 'production',
  optimization: {
    minimizer: [
      new rspack.SwcJsMinimizerRspackPlugin(),
      new rspack.LightningCssMinimizerRspackPlugin(),
    ],
  },
};
```

Specifying `optimization.minimizer` replaces the default minimizers. Include `SwcJsMinimizerRspackPlugin` to keep JavaScript minification enabled when configuring the CSS minimizer.

## Options

### include

- **Type:** `string | RegExp | (string | RegExp)[]`
- **Default:** `undefined`

Use this to specify which files should be minified, it matches the path of the output files.

### exclude

- **Type:** `string | RegExp | (string | RegExp)[]`
- **Default:** `undefined`

Use this to specify which files should be excluded from minification, it matches the path of the output files.

For example, skip an emitted file named `vendor.css` while still minifying other CSS assets:

```js
new rspack.LightningCssMinimizerRspackPlugin({
  exclude: /vendor\.css$/,
});
```

This matches output filenames, not source paths such as `src/vendor.css`. It is separate from `minimizerOptions.exclude`, which controls CSS syntax transformations.

### test

- **Type:** `string | RegExp | (string | RegExp)[]`
- **Default:** `undefined`

Use this to provide a pattern that CSS files are matched against. If the output filename matches the given pattern, it will be minified, otherwise it won't be.

### removeUnusedLocalIdents

- **Type:** `boolean`
- **Default:** `true`

Whether to automatically remove the unused local idents of CSS Modules, including unused CSS class names, ids, and @keyframe names. The declarations of these will be removed.

For example, in the following CSS Modules, class names a and b are exported, but only class name a is used in the js file:

```css title=index.module.css
.a {
  color: red;
}

.b {
  color: blue;
}
```

```js title=index.js
import * as styles from './index.module.css';
document.body.className = styles.a;
```

At this point, the information that class name b is unused will be obtained via Rspack's tree shaking feature and provided to lightningcss. During minimization, the declaration for class name b will be removed from the CSS output, resulting in the following final output:

{/* prettier-ignore */}
```css
.a{color: red}
```

### minimizerOptions

Configuration passed to Lightning CSS for minification.

Below are the configurations supported, `targets` configuration is plain browserslist query, for other detailed usage, please refer to [Lightning CSS documentation](https://lightningcss.dev/transpilation.html)

:::info

1. The plugin determines `targets` in this order:
   - Use `minimizerOptions.targets` if explicitly configured.
   - Otherwise, inherit the target data from Rspack's [`target`](/config/target#default-behavior), keeping only supported browsers. If it contains no supported browsers, as with `browserslist:node 18`, use an empty target object.
   - If Rspack provides no target data, as with `web`, use `"fully supports es6"` by default.

   During minification, Lightning CSS may use shorter, newer syntax to reduce file size. This default limits the syntax it can use to keep the result compatible with those browsers.

2. `minimizerOptions.include` and `minimizerOptions.exclude` default to no forced or excluded features. Lightning CSS uses `targets` to decide which syntax transformations are needed. Use feature objects such as `include: { nesting: true }` to force a transformation, or `exclude: { nesting: true }` to prevent it.

We recommend and encourage users to configure their own `targets` to achieve the best minification results.
:::

For example, target Chrome 100 and later. This configuration uses [built-in CSS support](/guide/languages/css#built-in-css-support) and keeps both JavaScript and CSS minification enabled:

```js title="rspack.config.mjs"
import { rspack } from '@rspack/core';

export default {
  mode: 'production',
  devtool: false,
  entry: './src/index.js',
  output: {
    cssFilename: '[name].css',
  },
  module: {
    rules: [{ test: /\.css$/i, type: 'css' }],
  },
  optimization: {
    minimizer: [
      new rspack.SwcJsMinimizerRspackPlugin(),
      new rspack.LightningCssMinimizerRspackPlugin({
        minimizerOptions: {
          targets: ['chrome >= 100'],
        },
      }),
    ],
  },
};
```

```js title="src/index.js"
import './style.css';
console.log('Hello');
```

```css title="src/style.css"
.card {
  color: red;

  &:hover {
    color: blue;
  }
}
```

Since Chrome 100 does not support CSS nesting, the minimizer flattens the nested rule and emits:

{/* prettier-ignore */}
```css title="dist/main.css"
.card{color:red}.card:hover{color:#00f}
```

Setting `minimizerOptions.exclude` to `{ nesting: true }` would preserve the nested rule even with these targets, so the result would require browsers that support nesting. Conversely, `include: { nesting: true }` forces nesting to be transformed even when all target browsers support it.

Unlike the plugin's top-level `include` and `exclude`, these feature options do not select files. They control transformations within the CSS assets selected for minification.

```ts
type Targets = {
  android?: string;
  chrome?: string;
  edge?: string;
  firefox?: string;
  ie?: string;
  ios_saf?: string;

type LightningCssMinimizerOptions = {
  errorRecovery?: boolean;
  targets?: string[] | string | Targets;

  exclude?: LightningcssFeatureOptions;
  drafts?: Drafts;
  nonStandard?: NonStandard;
  pseudoClasses?: PseudoClasses;

  oklabColors?: boolean;
  labColors?: boolean;
  p3Colors?: boolean;
  hexAlphaColors?: boolean;
  spaceSeparatedColorNotation?: boolean;
  fontFamilySystemUi?: boolean;
  doublePositionGradients?: boolean;
  vendorPrefixes?: boolean;
  logicalProperties?: boolean;
  selectors?: boolean;
  mediaQueries?: boolean;
  color?: boolean;

```
