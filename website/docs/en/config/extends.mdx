# Extends

Use `extends` to share Rspack settings across projects or environments. Keep common settings in a base configuration and override individual options in the configuration that extends it.

- **Type:** `string | string[]`
- **Default:** `undefined`

`extends` is available only in [`@rspack/cli`](/api/cli). If you use the JavaScript API, you can merge them explicitly with [rspack-merge](/config#rspack-merge).

## Basic usage

Set `extends` to the path of a configuration file. You can use an absolute path or a path relative to the file that declares `extends`. The base configuration can also be a JSON file, such as `./base.rspack.config.json`.

<Tabs>
  <Tab label="ESM">

```js title="rspack.config.mjs"
export default {
  extends: './base.rspack.config.mjs',
  output: {
    filename: '[name].bundle.js',
  },
};
```

  </Tab>
  <Tab label="CJS">

```js title="rspack.config.cjs"
module.exports = {
  extends: './base.rspack.config.cjs',
  output: {
    filename: '[name].bundle.js',
  },
};
```

  </Tab>
</Tabs>

## Multiple configurations

List the configurations you want to extend in an array. For options such as `mode`, a value in the current configuration takes precedence. Otherwise, the first configuration in the list that sets the option wins.

```js title="rspack.config.mjs"
export default {
  extends: ['./dev.config.mjs', './web.config.mjs'],
  output: {
    filename: '[name].js',
  },
};
```

If both files set `mode`, this example uses the value from `dev.config.mjs`. Objects and arrays have their own merge rules.

- Objects merge by property. The example overrides `output.filename` and keeps an inherited `output.publicPath`.
- Arrays such as `plugins` and `module.rules` are concatenated. In this example, plugins from `web.config.mjs` come first, followed by those from `dev.config.mjs`, then any plugins you add to `rspack.config.mjs`.

## Node modules

To extend a configuration from an installed package, use its package name. The package must export a Rspack configuration.

```js title="rspack.config.mjs"
export default {
  extends: 'some-rspack-config-package',
};
```

## Nested extends

A base configuration can have its own `extends`. For example, if `dev.config.mjs` extends `./shared.mjs`, the CLI looks for `shared.mjs` in the same directory as `dev.config.mjs`.

If both `dev.config.mjs` and `web.config.mjs` extend `shared.mjs`, its settings are merged twice, once through each file. A plugin registered in `shared.mjs` is applied twice. To apply it once, move it from `shared.mjs` to `rspack.config.mjs`.

If the CLI reports `Circular extends chain: dev.config.mjs -> shared.mjs -> dev.config.mjs`, each file extends the other. Remove one of those `extends` references to break the cycle.
