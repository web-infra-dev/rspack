## `renderContent`

`SyncWaterfallHook<[Source, RenderContext]>`

Called with the rendered content of a JavaScript chunk, before the chunk's init
fragments are injected and before the chunk is written out. Taps must return a
`Source`, which becomes the content the following taps and the rest of the
rendering pipeline see.

Use it to wrap the whole chunk content, for example in a `try`/`catch`:

```js title="rspack.config.mjs"
class WrapChunkPlugin {
  apply(compiler) {
    const { ConcatSource } = compiler.rspack.sources;
    compiler.hooks.compilation.tap('WrapChunkPlugin', (compilation) => {
      const hooks =
        compiler.rspack.javascript.JavascriptModulesPlugin.getCompilationHooks(
          compilation,
        );
      hooks.renderContent.tap('WrapChunkPlugin', (source, { chunk }) => {
        if (chunk.name !== 'background') return source;
        return new ConcatSource('try {\n', source, '\n} catch (e) {}');
      });
    });
  }
}
```

`RenderContext` carries the `chunk` being rendered:

```ts
type RenderContext = {
  chunk: Chunk;
};
```

webpack additionally exposes `chunkGraph`, `moduleGraph`, `runtimeTemplate`,
`codeGenerationResults` and `runtimeRequirements` on the render context. In
Rspack those are reachable from the `compilation` the hooks were retrieved from,
so only the per-call `chunk` is carried across the binding.
